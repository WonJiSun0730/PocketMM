# 치트: 실제 채팅 도착 시간

## 확인 방법

브랜치 업데이트 후 프론트엔드를 새로고침한다. 개발자 도구(치트)의 **실제 채팅 도착 시간**에서 확인한다. 데스크톱과 모바일 도구에 동일한 기록을 표시한다.

Pocket에서 메시지를 직접 보내면 다음 값을 자동으로 기록한다. 별도의 유료 측정 요청은 만들지 않는다.

| 항목 | 기준 |
| --- | --- |
| 본문 수신 | 전송 핸들러 진입 → 브라우저가 preview 이벤트의 전체 본문을 읽고 파싱한 시점 |
| 화면 표시 추정 | 같은 시작점 → 본문 DOM이 연결되고 탭이 활성인 상태에서 두 animation frame이 지난 시점 |
| 검사·기억 처리 완료 | 같은 시작점 → 브라우저에서 complete 이벤트를 받은 시점. 기존 서비스의 커밋·AFTER_COMMIT 기억 처리 완료 후 전송되는 이벤트다. |
| 다음 입력 준비 | 같은 시작점 → 화면·기억 진단 조회 후 전송 중 상태가 해제된 React 커밋 이후 |
| 요청 전송 시작 | 같은 시작점 → 부재 활동 확인을 거쳐 채팅 fetch를 시작하기 직전 |
| 수신 후 후속 처리 | complete 수신 − preview 수신. 네트워크·버퍼링 영향을 포함하므로 순수 기억 저장 시간이라고 해석하지 않는다. |

모든 경과 시간은 performance.now() 차이를 사용한다. 기록 시각만 ISO 벽시계를 사용한다. 준비 중 대기도 체감 시간에 포함한다. 본문을 받으면 해당 본문 시작으로 스크롤한다. 글자 단위 첫 토큰 도착 시간은 아니다.

## 통계·저장

- 같은 브라우저·Pocket별 최근 요청 100건을 localStorage에 저장한다. 치트를 닫아도 직접 채팅 계측은 동작한다.
- 최신 요청의 각 구간과 완료 요청의 구간별 최소·최대·평균·표본 수를 표시한다. 최근 요청 10건은 펼쳐볼 수 있다.
- 실패·중단은 별도로 표시하고 완료 요청 통계에서 제외한다. 구간 미측정은 0으로 바꾸지 않는다. 탭 비활성 시 화면 표시 추정은 제외하며 수신·완료 값은 남는다.
- 새로고침 시 진행 중으로 남아 있던 기록은 중단·완료 미확인으로 읽는다. 서버 실행 취소·실패를 확정하거나 자동 재시도하지 않는다.
- 시간 기록 JSON 다운로드 및 초기화가 가능하다. 기존 장기 테스트 JSON 내보내기에도 browserChatTiming 필드를 추가했다.
- 본문·입력·인증 정보·잔액은 별도 시간 저장소에 보관하지 않는다. 메모용 실제 잔액 $6.86을 앱에서 조회한 값으로 표시하지 않는다.
- 브라우저 저장이 차단되면 이번 화면에서는 계속 계측하고 보존 불가 안내를 표시한다. 다른 기기/브라우저/사이트 주소로 기록이 공유되지는 않는다.

## 해석의 한계

화면 표시는 DOM과 animation frame 기반 추정이다. 실제 모니터 출력·사용자의 시선·오버레이에 가려진 상태까지 측정하지 않는다. preview가 실제 프레임 전에 제거되고 확정 메시지만 보인 경우, 새 확정 메시지가 표시되는 프레임을 사용하며 연결되지 않은 DOM은 표시됐다고 기록하지 않는다.

이번 치트 기록은 실제 사용자 Pocket 일반 채팅의 브라우저 계측이다. 서버에서 직접 서비스를 부르는 자동 QA는 이 스트림·화면을 지나지 않으므로 이 통계에 섞지 않는다. 자동 QA의 기존 전체 처리 시간을 체감 도착 시간으로 이름만 바꾸지 않는다. 기존 57턴에는 이 값이 없어 소급 기록할 수 없다.

## 무료 검증

프론트엔드 테스트 16개 통과: 구간별 독립 계측, 완료 요청 통계, 0/누락/실패 처리, 재조회 중단 표시, Pocket별 분리, 오래된 콜백 차단, 비활성 탭 제외, 100건 제한, 저장 차단 대응, 두 프레임·DOM 연결 조건 및 기존 스트림/모델/예산 동작. Vite 프로덕션 빌드 통과. 유료 API는 실행하지 않았다.
