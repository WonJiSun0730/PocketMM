# QA 비용: 응답 대기와 과금 미확인 구분

exp-b7c6b4b118f6038c0f0f3c76의 사용자 내보내기(Downloads/10221546)와 실행 폴더를 읽어 대조했다. 첨부 JSON은 RUNNING/TARGET_IN_FLIGHT 도중 스냅샷이며 마지막 UNKNOWN은 REQUEST_STARTED 상태의 임베딩 호출이었다. 예산 uncertain=false, phase=RESERVED였다. API 실패나 과금 유실로 확정할 기록이 아니었다. 화면/CSV/JSON은 내려받은 시점이 달라 턴 수와 비용이 다를 수 있다.

실시간 확인 시 장부의 호출 ID별 마지막 영수증 비용 합계 $0.48077266은 budget.json.actualUsd와 같았다. run.json의 완료 턴 중심 체크포인트 합계는 $0.42810338이었고 나머지는 진행 중인 다음 턴 호출이었다. 비용 차이를 실패한 호출이나 이중 과금으로 단정할 수 없다.

사용 가능 잔액은 최대 예산 - 실제 지출 - 예약액이다. 예를 들어 기록된 Sol 전송 직전 실제 지출 $0.42853528, 예약액 $0.27453이면 잔액은 $9.29693472다. 예약액이 전부 실제 지출은 아니다. 응답이 오면 실제 비용으로 정산하고 나머지를 해제한다. 사용자가 본 $0.3743→$0.4285는 약 $0.0542 증가 구간이며, 완료 턴 경계뿐 아니라 다음 턴의 준비/보조 호출도 포함할 수 있다. 완료 10턴째 자체 호출 비용은 $0.05394619였다.

## 수정

- UNKNOWN으로 시작하는 호출 중 실행 중이고 worker가 살아 있는 REQUEST_STARTED만 응답 대기로 분류한다. 정상 대기를 CALL_STATUS 오류 목록에 넣지 않는다.
- worker가 종료됐거나 실패/중단 상태이거나 응답은 왔지만 사용량을 받지 못한 호출은 대기로 숨기지 않는다. 과금 미확인 경고와 보호를 유지한다.
- 기존 unknownCalls는 미정산 비용 총수로 그대로 보존하고 pendingCalls를 추가한다. 화면은 응답 대기와 나머지 과금 미확인을 구분한다. 미확정 금액을 0으로 합산하지 않는다.
- 같은 callId가 체크포인트에 있어도 최신 장부 영수증으로 갱신한다. 오래된 UNKNOWN이 응답 후에도 남는 문제를 막는다. 턴 번호는 기존 값을 보존한다.
- 작은 임베딩 비용을 소수 8자리까지 표시하여 $0.0000007 같은 금액을 $0.0000으로 보이지 않게 한다.
- 잔액의 예약액 차감과 진행 중인 턴 비용 포함을 화면에 설명한다. 지출 계산/예약/모델/호출 횟수는 바꾸지 않는다.

무료 검증: 백엔드 UI·분석·예산 테스트 23개, 프론트엔드 요청/모델/금액 표시 테스트 4개 통과. 실행 중 대기→worker 종료 시 과금 미확인→응답 정산으로 비용 확정되는 경로를 검증했다. 유료 API 호출이나 실행 중인 사용자 테스트 중단은 하지 않았다.
