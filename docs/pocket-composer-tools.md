# Pocket 입력 도구와 문장 추천

입력창 왼쪽의 큰 `*` 버튼은 선택 영역을 별표로 감싼다. 선택 영역이 없으면 `**`를 삽입하고 커서를 사이에 둔다. 선택이 있으면 내부 글자의 선택을 유지한다. 노트 버튼은 문장 추천 토글이며 방을 열면 기본 꺼짐이다. 추천을 누르면 입력창에 넣고 편집할 수 있으며 자동 전송하지 않는다.

## 호출과 비용

- 꺼진 상태는 추천 호출 0회다. 켜진 동안 저장된 새 AI 지문(처음에는 인트로)마다 1회 호출로 3개를 생성한다.
- 모델은 OpenAI `gpt-5.6-luna`로 고정하며 본문·QA 대상·테스트 플레이어 설정은 변경하지 않는다. reasoning=none, max_output_tokens=800이다. 각 후보는 행동 지문 최대 한 문장(80자), 대사 최대 한 문장(120자)이며 한쪽은 생략할 수 있다.
- 최근 대화 최대 4개, 현재 본문 최대 6,000자, 인트로·플레이어 설명·노트·현재 상태 일부를 제한된 길이로 제공한다. 별도 장기기억 검색·임베딩·연속성 검사·재생성을 호출하지 않는다. 추천 때문에 대화/시간/상태/기억을 저장하지 않는다.
- 같은 지문의 토글 반복은 생성 중 요청/완료 결과를 재사용한다. 꺼진 동안 새 지문에 대해서는 생성하지 않는다. 호출 전 즉시 끄면 전송하지 않지만 이미 전송된 호출은 비용을 되돌릴 수 없다. 켠 채 100개의 새 지문을 보면 추천 호출도 최대 100회 추가된다. 실행 위치와 비용은 별개다.
- 서버는 `data/pocket-reply-suggestions/{sessionId}/{sceneHash}.json`에 생성 예약과 결과를 보관한다. 같은 지문을 새로고침하거나 서버 재시작 뒤 열어도 재생성하지 않는다. 서버 저장소가 같을 때 동시 요청도 예약 파일의 CREATE_NEW로 한 번만 호출한다. 이 디렉터리는 Git에서 제외한다.
- 실패한 생성은 해당 지문에서 자동 유료 재시도하지 않는다. 서버 중단으로 PENDING 예약만 남아도 중복 호출하지 않고 상태를 알린다. 다른 창에서 생성 중인 요청은 PENDING으로 표시하며 자동 폴링하지 않는다. 캐시 파일을 지우면 이 보호와 기존 추천이 사라진다. 이전 기록은 자동 삭제하지 않는다.
- AI 사용량은 REPLY_SUGGESTION(문장 추천)으로 별도 집계하며 본 대화의 최근 사용량을 덮어쓰지 않는다. 실제 추천 비용은 입력/출력 사용량에 따라 달라지며 유료 실측 없이 달러 금액을 단정하지 않는다.

## 장면 일치와 보안

추천 API는 먼저 방 소유권과 world/room/session을 검증한다. 현재 메시지 ID·선택 variant·원문이 브라우저 요청과 다르면 새 유료 호출 전에 거절한다. 지문 ID, variant, 본문과 세션 ID로 캐시 키를 만든다. 이전 장면의 늦은 응답은 새 장면 추천을 덮어쓰지 않는다. POST 요청은 사용자가 추천을 켠 경우에만 발생하며 응답은 no-store다. 캐시에는 추천 결과·상태만 저장하고 요청 프롬프트/인증은 저장하지 않는다.

서버 스냅샷과 실제 생성 사이에 대화가 바뀔 수 있다. 추천은 확정된 사건이나 정답이 아닌 편집 가능한 초안이며 전송 전 사용자가 판단한다. 일부 과거 정보와 긴 상태는 비용을 위해 생략한다. 실제 Luna 의미 품질은 모의 테스트로 입증하지 않는다.

## 무료 확인

모델 호출을 가로챈 테스트에서 Luna 고정·출력 상한·3개 구조·별도 사용량·본문 모델 유지, 장면 및 소유권 검사, 재시작/동시 요청/실패 후 중복 과금 방지를 검증한다. 화면 로직은 기본 꺼짐, 토글·생성 중 요청 재사용, 새 지문 갱신, 늦은 응답 격리, 실패 무재시도와 별표/이모지 선택을 검증한다.

Vite의 `/test-fixtures/pocket-composer.html`은 실제 컴포넌트를 사용하는 무료 모의 화면이다. API를 호출하지 않으며 모의 호출 수를 표시한다. 화면에서 별표 선택/커서·추천 토글 재사용·새 지문 1회·초안 삽입을 확인했다.

구조화 응답 형식은 [OpenAI 공식 문서](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses)를 참고하고 저장소의 기존 Responses 연결을 재사용한다.

## 실패 처리 보완

초기 버전은 실패 이유를 버리고 FAILED만 보관했다. 이미 이 형식으로 저장된 실패의 HTTP/모델/파서 원인은 소급 복구할 수 없다. 캐시를 지우거나 유료 재시도하지 않고 LEGACY_FAILURE로 표시한다.

문장 길이·별표·줄바꿈·여러 문장은 원문 범위에서 로컬 정규화하고 행동/대사를 각각 최대 한 문장으로 줄인다. 중복·빈 후보는 제외하며 1~2개만 유효해도 PARTIAL로 표시해 다른 후보까지 폐기하지 않는다. 추가 API 호출은 없다. 공급자별 스키마 제약 호환성을 위해 문자열 길이·배열 개수 조건은 프롬프트 및 로컬 정규화에서 처리하고 전송 스키마는 기본 구조만 사용한다. 정상 목표는 여전히 후보 3개, 동일 Luna와 800토큰 상한이다.

새 실패에는 errorCode와 안전한 사용자 메시지를 보관한다. HTTP 거절의 상태와 제한된 code/param 값만 사용하며 공급자의 임의 message/본문은 노출하지 않는다. 서버 로그도 세션·장면 키·안전한 코드·예외 타입만 남긴다. 응답 파싱 실패 시 생성된 후보 텍스트만 최대 16,000자로 제한해 별도 .failure.json에 보관한다. 요청 프롬프트·인증·공급자 응답 envelope는 저장하지 않는다. 새 지문의 실패는 화면/로컬 기록으로 구분할 수 있으며 자동 재시도하지 않는다.

브라우저 자동완성 경고를 줄이기 위해 입력창에 id/name을 부여했다. 이 경고는 추천 모델 호출 실패의 근거가 아니다.
