# 생성 전 기억 조회 대기 개선

## 변경

1. `HybridMemoryRetriever`: 검색 후보 모두의 semanticMemory가 null이면 기존 일반 순위 결과를 즉시 반환한다. 이 조건에서 결과에 사용되지 않던 질의 임베딩 호출을 생략한다. 실제 벡터 후보가 있는 경우의 벡터/일반 순위 결합은 유지한다.
2. `MemoryRepository.findForWorldRoomRecall`: 포켓·인물·현재 시각 조건과 기존 기억 시각/ID 내림차순을 DB에서 적용한다. 인물마다 포켓 전체 기억을 가져온 뒤 필터링하던 범위를 줄인다. Java의 인물/미래 기억 필터도 유지한다. 인물별 조회 횟수를 한 번으로 합친 것은 아니며 읽는 행의 범위를 줄인 변경이다.
3. Pocket 기억 조회의 직접 접근 상태를 최대 256개씩 projection으로 읽는다. 압축 없는 일반 경로에서 후보마다 반복하던 findByMemoryId를 제거한다. provenance의 상속 제한, 접근 강도 감산, 기억 시각·감쇠·회상 기준 및 접근 기록 갱신을 유지한다.
4. 압축은 별도 트랜잭션에서 상태를 바꿀 수 있으므로 시도 직전에 접근 상태 스냅샷을 무효화한다. 현재 후보의 압축 이후와 다음 후보부터 기존 개별 최신 조회로 돌아간다. 압축의 권한 확인/근거 검증/영속화 경로는 생략하지 않는다. 요청 사이에는 권한을 캐시하지 않는다.
5. `MemoryQueryEmbeddingScope`: 한 WorldRoomContextBuilder의 활성 인물 기억 구성 동안, 같은 provider 인스턴스·namespace·정확한 최종 검색문에 대한 성공한 질의 벡터만 재사용한다. 후보 목록/접근 상태/검색 결과/문서 벡터는 이 캐시에 넣지 않는다. 중첩 구성은 별도 범위를 열고 부모 범위를 복구하며 예외 뒤에도 ThreadLocal을 제거한다. 빈 벡터·실패는 숨기지 않는다.

검색문은 기존 PocketMemoryQuery.focus 처리 이후의 값이다. 원래 사용자 입력이 같아도 인물의 기억 근거에 따라 검색문이 다르면 공유하지 않는다. 벡터는 불변 복사본으로 보관하고 범위 종료 시 버린다. 새로운 스레드·영속 작업·외부 API 종류나 모델 변경은 없다. 일반 채팅과 QA의 동일 문맥 구성 경로에 적용된다. 1:1 legacy 기억의 접근 상태 조회는 기존 경로를 유지한다.

## 절감 근거

- 벡터 후보가 전혀 없는 유효 검색: 질의 임베딩 1회가 0회가 된다. 후보가 비어 있을 때의 조기 반환은 원래 있었으며 이번 변경과 구분한다.
- 한 문맥에서 같은 모델·같은 최종 질의를 C번 검색하면 질의 벡터 생성은 1회로 줄일 수 있다. 질의가 다르거나 활성 인물이 한 명이면 이 재사용 절감은 없다. 기억 문서 임베딩의 기존 지문 캐시는 계속 별도 적용된다.
- 압축 없는 Pocket 조회에서 차단되지 않은 후보 N개에 대한 직접 접근 상태 조회는 대략 2N번에서 ceil(N/256)번의 일괄 조회로 줄어든다. 차단 후보는 기존에도 첫 검사 뒤 제외됐다. provenance 조회와 압축 경로의 추가 조회를 포함한 전체 SQL 수는 아니다.
- 전체 세션 기억을 인물마다 읽는 대신 해당 인물의 현재 시각까지의 기억만 읽는다. 후보 선정/정렬/최대 회상 개수를 축소해 얻는 절감은 아니다.

현재 상세 계측을 포함한 새 사용자 QA 기록이 없어 실제 절감 초나 달러·비율을 제시하지 않는다. 유료 API로 성능 비교를 실행하지 않았다. 시간 변경→기억 조회의 순서와 압축·접근 기록 트랜잭션은 그대로이며, 남은 독립 작업의 병렬화는 이 범위에 포함하지 않는다.

## 무료 검증 기준

벡터 후보 없음의 결과 동일/외부 호출 0회, 실제 벡터 후보의 검색 결과 격리, 같은 질의의 1회 생성, 다른 모델/검색문/provider/새 문맥/중첩 문맥의 격리, 예외 뒤 범위 정리를 검증한다. 접근 상태 일괄화는 BLOCKED·IMPLICIT·상속 차단·미래 기억 제외와 다음 호출의 권한 변경을 확인한다. 압축으로 현재/후속 후보가 차단되는 상황에서는 오래된 일괄 결과를 쓰지 않는지 확인한다. 실제 H2 쿼리로 포켓·인물·시각 경계도 확인한다.

기존 기억 회상/접근 경계/provenance·임베딩 저장·월드라인과 실제 서비스 경로 모의 QA 100턴 검증도 함께 실행한다. 모의 검증은 실제 장기 대화 의미 품질이나 유료 속도 개선의 증명이 아니다.

최종 무료 오프라인 테스트 **78개 통과, 실패/오류/스킵 0개**. 새 직접 검증 외에 기존 회상 19개, 접근 경계 6개, provenance 통합 7개, H2 월드라인 14개, 예산 17개와 모의 QA 100턴/검사 오류 80건 시나리오를 포함한다. 프론트엔드는 이번에 변경하지 않았다. 유료 API·사용자 실행 재개·데이터 변경은 하지 않았다.

## 적용

기존 PR 브랜치를 pull하고 진행 중 QA 종료 후 백엔드를 재시작한다. 기존 실행은 소급 변경·자동 재개하지 않는다. 새로운 scope 클래스를 서버/워커 코드 해시에 포함했다. 프론트엔드·본문 타이핑·대상/플레이어 모델·예산 예약과 과금 불명 차단 정책은 변경하지 않았다. 다음 승인된 실행의 CONTEXT_MEMORY_RECALL/CONTEXT_BUILD와 firstTokenMs를 비교한다.
