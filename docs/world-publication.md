# 월드 배포

홈의 배포 메뉴(`/deployments`)에서 배포된 월드를 표지 카드로 탐색한다. 카드는 월드 이름,
표지, 해시태그, 전체 포켓의 대화 턴 합계, 배포자 표시 이름을 제공한다. 목록은 24개씩
페이지를 나누며 대화 원문과 이용자 정보는 전달하지 않는다.

## 제작과 플레이

세계 → 월드 배포 관리에서 표지를 직접 업로드하고 해시태그를 저장한 후 배포한다.
표지와 인트로가 하나 이상 있어야 배포할 수 있다. PNG/JPEG 3MB 이하, 4096px 이하만
허용하며 파일 이름과 형식은 서버에서 검사한다. AI 이미지 생성이나 유료 호출은 하지 않는다.
해시태그는 `worlds.hashtags` TEXT 컬럼에 정규화된 줄바꿈 구분 문자열로 저장한다.
최대 10개, 태그당 30자이며 중복은 제거한다. 배포 시각은 nullable `worlds.published_at`이다.
기존 월드는 자동으로 배포되지 않는다.

배포 상세는 현재 표지·해시태그·플레이가이드와 해당 월드의 모든 인트로를 읽기 전용으로
제공한다. 제작자 전용 description, 로어, 캐릭터 비공개 설정, 다른 이용자의 메시지·기억은
이 API로 노출하지 않는다. 제작자가 이후 수정한 공개 내용은 즉시 반영된다.
배포 대화 턴 합계는 현재 DB에 남은 CHARACTER 메시지 수이며 입력·재생성 변형·부재 보고서는
중복 집계하지 않는다. 메시지나 포켓을 삭제하면 합계에서도 빠진다. 격리 QA 데이터는 포함되지 않는다.

인트로 선택 → 새로하기 → 플레이어 프로필 선택으로 항상 새 포켓을 만든다. 기존 포켓은
그대로 유지한다. 배포 경로에서만 해당 월드의 private 시작 공간을 사용할 수 있으며,
일반 private 공간 시작 경로의 접근 제한은 그대로 유지한다. 포켓은 플레이한 이용자 소유다.
시작 시 인트로 내용을 기존 세션 스냅샷에 보존한다. 인트로 수정·삭제는 기존 제작자 권한
검사를 통과해야 하며 배포 API에는 해당 수정 기능 자체가 없다.

배포를 내리면 목록·상세·표지 조회와 새 시작을 막는다. 이미 시작한 포켓의 이용은
기존 소유권 검사 아래 계속 가능하다. 모든 배포 API는 로그인해야 사용할 수 있고,
private-test 모드의 추가 로그인 제한도 유지한다.

## 디자인

사용자가 제공한 PocketMM UI 디자인 가이드라인에 맞춰 기존 색상 토큰을 사용한다.
중성 배경·회보라색 단일 포인트, 표지 중심 카드, 15~16px 모바일 본문과 16px 입력,
데스크톱 왼쪽 메뉴·모바일 하단 메뉴를 적용한다. 장식 배지·호감도·가상 통계는 넣지 않는다.

## 서버 적용

MariaDB에서는 `deploy/sql/20261021-world-cover.sql`,
`deploy/sql/20261021-world-publication.sql`을 먼저 적용할 수 있다. 현재 프로젝트의
Hibernate update 설정도 동일 컬럼을 생성하지만 운영 DB 적용 여부는 배포 시 별도 확인한다.
표지 파일은 DB 바이트가 아닌 디스크 파일로 저장한다. `world.cover.directory`를
배포 후에도 유지되는 쓰기 가능한 폴더로 지정해야 한다. 예: `/opt/pocketmm/data/world-covers`.
환경 변수 `WORLD_COVER_DIRECTORY`로 지정할 수 있으며, 운영 배포 시 서비스 실행 계정이
해당 폴더에 쓰기 가능한지 먼저 확인한다.
DB와 함께 이 폴더도 백업한다. 파일은 인증된 이미지 API로 제공하며 임의 외부 URL은 받지 않는다.
교체된 표지는 즉시 삭제하지 않는다. 추후 정리 시 현재 참조 파일과 백업 보존 정책을 확인한다.

## 검증

외부 API 없이 H2 통합 테스트로 공개 전/후 조회, 소유자 권한, 다른 인트로 주입 차단,
새 포켓 생성과 기존 포켓 유지, 인트로 수정 차단, 턴 합산, 해시태그 저장, 이미지 검증 및
경로 이동 차단을 확인한다. HTTP 보안 테스트에서 비로그인 요청 차단과 요청 검증을 확인한다.
화면 검증용 임시 데이터는 운영 DB에 넣지 않는다.
