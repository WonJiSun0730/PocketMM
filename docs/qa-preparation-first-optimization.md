# 생성 전 대기 1차 개선

## 근거와 범위

46턴 `exp-5628cefa20bbd9089f30e495` 기록의 본문 준비 평균은 15.69초, 대상 HTTP 호출 평균은 약 11.70초다. 차이 약 3.99초에는 생성 준비뿐 아니라 QA 사전 계수와 요청 기록, 응답 파싱 등이 포함되어 있어 전부 DB 병목으로 해석하면 안 된다. 시간 판단 43회는 모두 대상 생성보다 먼저 끝났으며 평균 약 1.79초, 최대 약 3.47초였다.

시간 판단의 기존 단순 부분 문자열 검사에는 `낮`, `뒤`, `후`, `다음` 등이 포함되어 있었다. 이 때문에 `낮게 말했다`, `몸을 낮췄다`, `뒤쪽`, `다음 교차로`에도 규칙 해석 실패 후 시간 AI를 호출했다. 실제 38/39/46턴의 해당 호출은 약 1.61/1.84/1.52초였다.

## 변경

- `HybridTimeInterpreter`: 규칙 해석 우선순위는 보존하고 시간 AI 진입 조건을 구체적인 시각·기간·시간대·대기/경과 표현으로 좁혔다. 일상 행동의 동음/부분 문자열로 생기는 추가 호출을 줄인다. 일반 사용자와 QA의 동일 경로에 적용된다.
- `ExperienceInputCounter`: QA의 HTTP 클라이언트와 임베딩 토크나이저를 각각 지연 초기화하여 재사용한다. 키는 요청마다 설정하고 입력 토큰 결과를 캐시하지 않는다. 공급자 사전 계수, 유효성 확인, 예산 예약과 전송 차단은 그대로 둔다. 원격 계수 왕복 자체는 남는다.
- `WorldRoomContextBuilder`: 한 문맥 구성 안에서 세션 시스템 목록과 시스템별 상태 라벨을 한 번씩 읽고 두 DTO 구성에서 공유한다. 시스템 N개 기준 기존 `2 + 2N`회 repository 조회가 `1 + N`회로 줄어든다. 다른 메서드의 조회나 JPA 추가 지연 로딩까지 포함한 전체 SQL 감소량은 아니다. 다음 문맥 구성은 다시 읽으므로 변경된 현재값을 관찰한다.

초기 장면/시간/장면 지시 이후에는 실제 상태가 바뀔 수 있으므로 전체 문맥 재구성을 무조건 생략하지 않는다. 장기기억 검색·저장, 연속성 승인, 트랜잭션 순서를 유지하며 JPA 엔티티를 별도 스레드로 넘기지 않는다. 대상/플레이어/내부 판단 모델 설정과 생성 본문 분량도 변경하지 않는다. 토큰 스트리밍은 후속 단계다.

## 기대 효과와 한계

오탐이 발생한 턴에서는 그 시간 AI 호출의 대기·토큰 비용을 제거한다. 위 3개 실측 예시는 약 1.5~1.8초의 제거 가능한 구간에 해당하지만, 변경 후 전체 턴 지연 감소를 실측한 값은 아니다. 정확한 시간 판단이 필요한 턴에는 이 절감이 없다. 클라이언트/토크나이저 초기화와 중복 DB 조회 감소의 실제 초 단위 효과는 새 계측으로 확인해야 한다. 전체 속도나 비용의 고정 절감률은 제시하지 않는다.

남은 위험은 한국어 자유 표현에 대한 시간 AI 진입 누락이다. 명시적인 시간·기간과 경과 표현 회귀 테스트를 두었지만 언어 전체의 의미 정확도를 증명하지는 않는다. 장기기억 의미 품질 역시 모의 테스트만으로 판정할 수 없다. 다음 실행에서는 `TIME_INTERPRETATION`, `CONTEXT_BUILD`, `TARGET_TOKEN_COUNT`, `targetDispatchMs`, `bodyReadyMs`를 비교한다. 유료 재실행은 별도 승인 후에만 수행한다.

## 적용

무료 오프라인 검증은 관련 고유 테스트 73개 통과다. 시간 판단 22개, 수면/복합 시간 13개, 의미 시간 해석 2개, 사전 계수 6개, 예산 15개, H2 월드라인 14개, 실제 서비스 경로 모의 QA 100턴 시나리오 1개를 포함한다. 100턴 시나리오는 검사 오류 80건에도 원문/검증 사실/영수증 복구를 보존하는 기존 검증이다. HTTP 계수 테스트는 mock 서버만 사용하며 매 요청 입력/인증·정수 계수 검증·임베딩 로컬 토크나이저를 확인했다. 시스템 상태 테스트는 한 번씩 조회하고, 후속 문맥에서 변경된 현재값을 다시 읽는 것을 확인했다. 유료 API와 실제 사용자 QA는 실행하지 않았다.

진행 중 QA 종료 후 브랜치를 pull하고 백엔드를 재시작한다. 새로운 실행부터 비교하며 이전 기록을 소급 수정하거나 자동 재개하지 않는다. 원본 checkout의 개인 설정/데이터/로그는 수정하지 않았다.
