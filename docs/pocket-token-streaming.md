# Pocket 본문 토큰 스트리밍

## 동작

OpenAI를 선택한 Pocket 생성은 Responses SSE를 읽으며 구조화 JSON의 루트 `reply` 문자열만 단계적으로 전달한다. 고정된 모델·프롬프트 정책·추론 설정·상태 필드는 유지하고, 스키마 속성 순서를 명시해 `reply`를 첫 필드로 둔다. 실제 출력에서 다른 필드가 먼저 나와도 루트 reply를 찾아 전달한다. 중첩된 메타데이터의 reply나 문자열에 인용된 키는 제외한다. JSON 이스케이프와 UTF-8/유니코드 분할을 복원하며 메타데이터·판단 내용은 화면으로 보내지 않는다.

일반 메시지의 기존 `/chat/stream`은 `started → delta* → preview → complete`를 보낸다. `delta.reply`는 중복 덧붙임을 피하는 누적 본문이다. `preview`는 전체 본문 생성 완료, `complete`는 기존 승인·커밋·AFTER_COMMIT 기억 처리 이후다. 생성/확인 중 다음 입력은 계속 잠근다. 브라우저 연결이 끊겨도 유료 요청을 자동 재전송하지 않으며 저장 상태를 다시 확인한다. 수정된 최종 본문과 미승인 시 저장 차단은 기존 정책을 유지한다.

### 수신 중 타이핑

스트림 본문은 `StreamingPocketReply`에 연결한다. 이전 구현은 preview에 일반 `RpText`를 사용하고 최종 refresh의 타이핑도 꺼서 타이핑 연출이 빠져 있었다. 새 구현은 요청별 커서를 유지하고 새 조각만 대기열에 추가한다. 네트워크 대기 시간을 미래 문자의 타이핑 시간으로 적립하지 않으며, 최종 응답이 도착해도 남은 타이핑을 강제로 끝내거나 이미 표시한 본문을 다시 시작하지 않는다. 대기열 소진 후 저장된 메시지로 교체한다. 최종 수정본은 공통 접두부까지만 유지한다. ‘바로 보기’, 모션 감소 또는 탭 비활성은 연출을 생략하며 서버 완료와 구분한다. 네트워크/서버 완료 시간은 이 표시 대기와 별도로 계속 기록한다.

무료 화면 재현: Vite 개발 서버의 `/test-fixtures/streaming-typing.html`에서 ‘모의 조각 전송 시작’. 실제 수신기와 표시 컴포넌트에 0/350/700ms 조각, 750ms 완료를 주입한다. API를 호출하지 않는다. 브라우저 확인에서 완료 전 중간 문구 표시 및 완료 후 남은 대기열 타이핑 모두 PASS였다. 예시 첫 표시 5ms/모의 완료 758ms/표시 완료 3044ms는 로컬 모의 화면 값이며 실제 모델 성능 수치가 아니다. 스크린샷을 별도 결과물에 보존했다.

토큰 전달 범위는 SceneContinuityService의 대상 생성 구간에만 연다. 초기 장면·BOOTSTRAP·REVIEW·VERIFY와 기억 판단은 본문 조각으로 노출하지 않는다. 중단/예외 뒤 ThreadLocal을 해제한다. 추가 생성 호출이나 별도 비영속 백그라운드 작업을 만들지 않는다. Gemini 및 다른 전송 화면의 브라우저 토큰 전달은 이 변경 범위가 아니다.

## QA와 비용

QA도 동일 대상 생성 경로로 `stream:true`를 보낸다. 비용 인터셉터가 스트림 전체를 먼저 버퍼링하던 경로를 바꿔, 수신 중 동일 파서로 첫 본문 조각 시점을 기록하고 마지막 response의 사용량으로 기존 장부를 정산한다. 정산 후 게이트웨이에는 terminal JSON을 넘겨 중복 파싱·토큰 이벤트 재발행을 피한다. 입력 계수·출력 상한·최대 비용 예약은 그대로 유지한다.

완료/불완전/실패 terminal이 있으면 확인 가능한 사용량을 보존한다. incomplete/failed 대상은 저장 가능한 정상 턴으로 파싱하지 않는다. terminal 없이 끊기면 사용량을 추정해 무료 처리하지 않고 예약·과금 미확인을 유지하며 추가 유료 호출을 차단한다. 자동 재시도는 없다.

## 계측

- 실제 브라우저 치트: `firstTokenMs`(첫 본문 조각 수신), `receivedMs`(전체 preview), `displayMs`(첫 화면 표시 추정), 처리 완료와 다음 입력 준비를 구분한다. 최근 100건의 시간 메타데이터만 보관한다.
- QA: 요청 시작 기준 서버 `firstTokenMs`, `bodyReadyMs`, 검사 완료, 기억 포함 완료를 기록한다. 첫 본문 조각은 JSON 접두부나 reasoning 이벤트가 아닌 화면에 전달할 본문 문자열을 해독한 시점이다. 실제 브라우저 도착 시간은 아니다.
- QA 치트의 최소/최대/평균/표본, JSON, Markdown, metrics CSV `qa_first_token_ms`에 연결했다. 기존 기록과 mock/no-delta 응답은 첫 토큰 미측정으로 남긴다. 중단 요청의 부분 시점은 완료 평균에 넣지 않는다.

공식 규약: [OpenAI streaming responses](https://developers.openai.com/api/docs/guides/streaming-responses). `response.output_text.delta`와 terminal response를 사용한다.

## 검증과 한계

무료 백엔드 59개 통과: SSE 분할 수신·한국어/이스케이프/이모지·메타데이터 비노출, terminal 도착 전 전달, 선택 Sol의 단일 요청/사용량 보존/불완전 응답 거부, QA의 실시간 수신·정산·연결 중단 보호, 치트 내보내기와 과거 공란, 기존 H2 월드라인 14개 및 모의 실제 서비스 100턴/검사 오류 80건의 원문·검증 사실·복구 보존을 포함한다. 브라우저 로직 14개와 Vite 프로덕션 빌드 통과, 변경 화면 lint 오류 없음(기존 hooks 경고 유지).

타이핑 연결 보완 후 관련 백엔드 25개, 화면 로직 22개 및 프로덕션 빌드 통과. 조각 추가 시 커서 보존, 네트워크 공백, 최종 응답 후 대기열 소진, 수정본/이모지/다음 요청 초기화, 다른 루트 필드가 선행하는 SSE와 중첩 메타데이터 제외를 검증했다. 위 무료 브라우저 재현으로 실제 DOM의 중간 본문 표시도 확인했다.

유료 API·실브라우저 유료 속도 측정·기존 QA 재개는 실행하지 않았다. 따라서 실제 첫 조각까지 걸리는 시간, 프록시 버퍼링 영향과 속도 개선 수치는 미확인이다. 스트리밍은 본문을 읽기 시작할 시점을 앞당기며 생성 전 준비, 전체 생성·검사·기억 완료 대기와 비용 자체를 없애지 않는다. 미검증 본문이 먼저 표시되므로 검사 후 수정·실패할 수 있다. 이 상태를 화면에 표시한다.

진행 중 QA 종료 후 브랜치를 pull하고 백엔드 재시작·화면 새로고침 후 새 실행으로 측정한다. 서버/워커 해시에 파서와 전달 범위를 포함하므로 이전 실행의 결과를 소급 측정하거나 자동 재개하지 않는다. 유료 비교는 사전 승인 후에만 수행한다.
