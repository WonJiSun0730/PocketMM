# Pocket 텍스트 제공자 라우팅

OPENAI를 선택한 포켓의 대화, 초기 장면 설정, 편집 상태 분석, 시간 해석, 기억 추출,
임베딩, 기억 압축 및 부재 서사는 OpenAI를 사용한다. 두 키가 모두 있어도 Gemini를
우선하지 않는다. OpenAI 키 누락, 거절, 불완전 응답 또는 통신 실패 시 Gemini로
재시도하지 않는다. 기존의 시간 해석 실패 처리와 기억 압축 보류 정책은 유지한다.

텍스트 보조 모델은 `openai.memory-model`, `openai.time-model`,
`openai.compression-model`에서 설정한다. 기본값은 `gpt-5.6-luna`다.
임베딩 기본값은 `openai.embedding-model=text-embedding-3-small`이다.
대화 모델은 포켓의 기존 모델 선택을 따른다.

애플리케이션 진입점과 기억 검색은 세션 범위를 전달한다. 압축은 기억 자체의
포켓 소유 관계를 사용하므로 백그라운드 실행에서도 제공자를 식별한다.
임베딩 캐시 지문에는 제공자와 모델을 포함하여 기존 Gemini 벡터를 OpenAI 검색에
재사용하지 않는다. 과거 부재 서사를 다시 만들 때도 현재 포켓 설정을 조회한다.

이미지 생성은 별도 Gemini 기능이다. OPENAI 포켓에서는 자동·수동 생성 및
자동 생성 켜기를 서버에서 차단하고 안내한다. 대기 중 작업도 각 이미지 호출 전에
설정을 다시 검사한다. 저장 이미지 조회와 직접 첨부는 사용할 수 있다.

경험 QA는 대상 OpenAI 모델과 OpenAI 보조 파이프라인을 사용한다. 이전 Gemini
보조 설정을 가진 실행은 새 실행 생성이 필요하다. Google 키를 작업자에게 전달하지
않으며, 전송 보호기가 Gemini 요청과 다른 제공자의 토큰 계수 요청을 차단한다.
모든 OpenAI 보조 요청은 기존 `ExperienceTransport`의 공용 예산을 사용한다.
기존 최대 비용 예약, 잔액 검사, 역할별 출력 상한, 과금 미확인 시 예약 유지와
추가 호출 차단 정책을 유지한다. 임베딩은 입력 토큰만 예약·정산한다.

임베딩 계수는 [OpenAI 임베딩 가이드](https://developers.openai.com/api/docs/guides/embeddings)의
`cl100k_base`를 사용한다. 지원하지 않는 모델이나 입력 형식은 추정하지 않고 차단한다.
가격과 최대 출력 검증 정보가 없는 모델도 기존 정책대로 요청 전에 차단한다.

검증은 외부 유료 호출 없이 모의 HTTP 응답과 H2 통합 테스트로 수행한다.
`TextProviderRoutingTest`는 두 키 동시 설정, 시간·임베딩·압축의 실제 목적지,
키 누락 시 폴백 차단, 제공자 변경 및 과거 부재 맥락을 검사한다.
`ExperienceBudgetTest`는 기존 하드캡과 Gemini 전송 차단, OpenAI 임베딩 정산을 검사한다.
