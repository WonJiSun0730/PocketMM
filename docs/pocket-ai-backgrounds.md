# Pocket의 AI 배경·투명 원경

## 동작

첨부 시 입력한 키워드는 더 긴 장소 이름에도 적용된다. 예를 들어 ‘비밀기지’ 키워드로 ‘비밀기지 내부’를 재사용한다. 영문 키워드는 단어 단위로 찾으며, 명확한 장소 종류가 충돌하면 키워드만으로 재사용하지 않는다.

Pocket 설정 → 장소 배경에서 현재 장소 또는 입력한 장소를 확인한다. 저장된 같은 장소를 먼저 찾고, 같은 장소 종류의 키워드가 맞으면 기존 이미지를 재사용한다. 예: 상담실 ↔ 심리상담센터 상담실 ↔ counseling room. 침실/상담실, 실내/야외, 집/집으로 돌아가는 길은 구분한다. 제작자가 첨부한 장소 별칭도 재사용에 반영된다. 현재 저장 범위는 **동일 사용자 + 동일 월드**이고 그 안의 여러 Pocket이 공유한다. 다른 사용자의 개인 장소 이미지와 섞지 않는다.

자동 생성은 기본 ON이다. 재생되는 장소에 저장 이미지가 없으면 장면을 열 때 자동 생성한다. 설정에서 장소 이름을 입력하는 것만으로는 생성하지 않는다. 기존 카탈로그의 기본 OFF 값은 ON으로 전환하지만, 사용자가 설정 파일에 명시적으로 저장한 OFF는 보존한다. ‘저장 배경 찾기 / 새로 만들기’는 관리용 수동 요청이다. 같은 장소의 기존 이미지가 있으면 이 버튼도 재생성하지 않는다. 직접 첨부한 이미지는 같은 장소의 AI 이미지보다 우선한다. 자동 생성을 끄더라도 이미 요청한 생성은 완료된다.

POST는 생성 작업을 등록하고 202를 반환한다. 한 서버에서 생성 작업 하나씩 처리하며 최대 16개를 대기한다. 파일 카탈로그 잠금 후 재확인해 중복 결제 요청을 줄인다. 생성은 대화/기억/시간/감정 DB 트랜잭션과 분리된다. 배경·원경 다운로드와 캐릭터 모델 준비가 모두 끝나기 전에는 ‘주머니 안쪽을 들여다보고 있어요...’만 보여준다. 장면과 활동 설명을 숨기며 재생 타이머도 멈춘다. 준비 후 장면을 열고 해당 활동의 4초 재생을 시작한다. 생성·파일·모델 로딩 실패에는 기본 배경을 출력하지 않고 ‘다시 들여다보기’를 제공한다. 배경만 성공했다면 원경 재시도에서 그 배경 파일을 재사용한다. 재시작 후에도 완성 이미지와 미완성 배경은 디스크에 남는다.

## 크기와 레이어

기본 생성 모델은 gemini-3.1-flash-lite-image, 1K, 3:2다. 낮의 픽셀 아트와 비어 있는 캐릭터 공간을 요청한다. 240×160 논리 픽셀 PNG로 정리하고 nearest-neighbour로 확대한다. 작은 캐릭터의 기존 160px 내부 렌더와 비슷한 도트 밀도를 노린 선택이다. 실제 이미지의 구도·품질은 제공자 결과에 따라 검증해야 한다.

정사각 장면에서 배경은 화면 가로의 1.5배다. 300×300 내부 화면이면 450×300, 270×270이면 405×270이다. 화면의 중앙 부분을 보여주고 이동 시 가로 방향으로만 스크롤한다. 직사각 화면에서도 양 축을 덮고 3:2 비율을 유지한다.

배경(z=0) → 투명 원경(z=1) → 기존 3D 캐릭터(z=2) 순서다. 원경은 배경을 참고해서 같은 구도·팔레트로 만든다. 제공자가 진짜 alpha를 반환한다고 가정하지 않는다. 빈 부분을 순수 마젠타로 요청하고 서버에서 빈 공간과 구멍을 투명 PNG로 정리한다. 최소 10% 투명 공간과 최소 1% 그림이 있어야 통과한다. 불투명 원경은 적용하지 않는다. 배경 4초, 원경 7초 주기로 같은 방향으로 스크롤해 깊이감을 준다. 모션 줄이기 설정은 기존처럼 적용한다.

직접 첨부는 3:2 PNG/JPEG 배경과 alpha PNG 원경, 각 10MB 이하로 받는다. 파일을 디코딩해 크기/형식을 검사하고 같은 논리 픽셀 규격으로 저장한다. SVG 및 외부 URL 업로드는 받지 않는다.

## 생성 비용 비교 (2026-10-13)

| 방식 | 이미지 두 장 출력 비용 | 특징 |
|---|---:|---|
| Flash Lite Image 1K 원본 그대로 표시 | 약 $0.0672 | 작은 화면에서는 미세한 디테일이 도트 캐릭터와 어긋날 수 있음 |
| Flash Lite Image 1K → 240×160 → 픽셀 확대 (기본) | 약 $0.0672 | 생성비는 동일, 저장 용량과 도트 밀도에 유리 |
| Flash Image 512px → 픽셀 확대 | 약 $0.0900 | 낮은 해상도지만 현재 모델 단가가 더 높음 |

저비용 Lite 모델은 1K만 지원한다. 다운샘플링은 AI 생성비를 할인하지 않는다. 비용은 입력 토큰·재시도·세금을 제외한 출력 추정이다. 저장 이미지 재사용에는 생성비가 없다. 실패 후 재시도는 추가 호출 비용이 발생할 수 있다. 서버 디스크 용량 안에 파일로 저장하며 별도 저장 서비스는 사용하지 않는다.

공식 근거: [이미지 생성 규격](https://ai.google.dev/gemini-api/docs/image-generation), [가격](https://ai.google.dev/gemini-api/docs/pricing), [Generate Content REST 요청](https://ai.google.dev/gemini-api/docs/generate-content/image-generation).

## 실행·배포 설정

기존 GEMINI_API_KEY를 사용한다. 해당 계정에서 이미지 모델과 결제가 활성화되어 있어야 한다. 실제 유료 생성 결과는 이번 자동 테스트에서 호출하지 않았다.

로컬 기본 저장 경로: 실행 폴더의 data/pocket-backgrounds. Git과 배포 파일에 포함하지 않는다.

서버 권장 설정:

```ini
POCKET_BACKGROUND_DIRECTORY=/var/lib/pocketmm/backgrounds
POCKET_BACKGROUND_ENABLED=true
POCKET_BACKGROUND_MODEL=gemini-3.1-flash-lite-image
```

배포 서비스 예제에는 StateDirectory=pocketmm를 추가했다. 기존 서버의 서비스 파일을 유지한다면 배포 전에 직접 디렉터리를 준비하고 env에 경로를 넣는다:

```sh
sudo install -d -o pocketmm -g pocketmm -m 750 /var/lib/pocketmm/backgrounds
```

이미지 첨부를 위해 Nginx HTTPS 서버 블록에 client_max_body_size 21m이 필요하다. API 이미지 경로는 기존 /api/ 프록시를 사용하므로 공개 파일 경로나 새 정적 location은 필요 없다. 이미지는 Pocket 소유자 인증 후 반환한다. 릴리스 교체/롤백 때 /var/lib/pocketmm를 보존하고 백업에 포함한다.

## 검증

초기 구현에서 신규 백엔드 검사 10개와 기존 부재 처리 회귀 31개, 프론트 검사 29개 및 프로덕션 빌드를 통과했다. 자동 생성 기본값·준비 완료 게이트 보완 후 백엔드 7개와 프론트 32개 검사 및 빌드를 추가로 통과했다. 응답 본문 읽기 제한을 보완한 뒤 관련 제공자 검사 2개도 다시 통과했다.

저장/재시작/사용자 범위, 키워드 매칭, 투명 변환, 부분 성공 재시도, 동시 요청, REST 요청 규격과 이미지 응답 파싱, 외부 Pocket 접근 거부, 202 응답을 검사한다. 프론트 검사는 화면 비율과 기존 걷기 방향을 확인한다. 브라우저에서는 예시 이미지로 기존 두 VRM, 원경 alpha, 같은 방향의 서로 다른 스크롤 속도, 로딩 중 장면 비공개·재생 중단·준비 후 재생 재개·실패 시 미대체와 모바일 폭을 확인한다. 예시 화면은 실제 AI 생성 품질 검증으로 취급하지 않는다.

## 생성 실패 확인

GENERATING에서 FAILED로 바뀌면 비동기 생성 또는 저장 단계에서 실패한 것이다. available은 서버 설정과 키 존재 여부만 나타내며 모델 권한과 사용량 한도를 검증하지 않는다. 화면의 문제 확인을 열면 안전한 실패 이유를 확인할 수 있다. 서버에는 Pocket background failed와 session, phase(BACKGROUND/SCENERY/STORE), 예외 유형, 안전한 이유만 기록한다. 키·프롬프트·제공자 응답 본문은 기록하지 않는다.

Gemini 요청은 문자열 비율과 크기를 지원하는 generationConfig.imageConfig를 사용한다. 제공자의 400/401/403/404/429 응답, 응답 지연, 그림 없는 응답, 파일 저장 실패를 구분한다. 실제 계정에서의 생성 성공은 별도 확인이 필요하다. MailHealthIndicator의 메일 인증 오류는 이 이미지 생성 경로와 별개다.

## 원경 소품과 화면 분위기

신규 AI 원경은 공원의 벤치·쓰레기통, 거리의 삼각뿔·표지판 등 1~2개의 작은 소품만 요청한다. 건축물·아치·폐허를 금지하고 배경의 지면과 픽셀 밀도에 맞추며 잘린 소품과 마젠타 반사를 금지한다. 신규 생성 파일 정규화에서 어두운 보라색 잔색도 투명화한다. 기존 저장 파일과 직접 첨부된 alpha 이미지는 수정하지 않는다. 생성 모델의 지침 준수와 실제 새 이미지 품질은 별도 확인해야 한다.

장면 전체(배경·소품·모델·침대)에 CSS 합성 색 보정을 적용한다. 원본/포근하게/선명하게/부드럽게 프리셋과 밝기·따뜻함·색감·대비 게이지가 있으며 기본은 포근하게다. 하늘·구름·지형 변경이나 광원 재계산, bloom은 하지 않는다. 관리자 역할 DEVELOPER에게만 부재 활동 팝업 옆에 접이식 조절판이 보이며 좁은 화면에서는 아래에 배치한다. 값은 기기 브라우저에 저장되어 장면 간 공유하며 서버 전체 사용자 기본값을 변경하지 않는다. 생성 API 요청이나 비용은 추가되지 않는다.

부재 시간 테스트도 DEVELOPER 전용 접이식 영역으로 표시하고 simulate API는 ROLE_DEVELOPER 외 요청을 403으로 거부한다. 일반 시간 체크 ON/OFF와 최소 부재 시간 설정은 유지한다. 관련 백엔드 13개·프론트 33개 검사와 빌드를 통과하고 브라우저에서 관리자 조절판, 원본 전환, 모바일 배치, 일반 회원 도구 숨김을 확인했다.

## 시간대별 저장 및 화면 채움 (기존 조명 정책 대체)

장면의 simulatedAt을 API 요청과 이미지 메타데이터에 전달한다. 서버와 프론트는 06~09시 morning, 10~19시 day, 20~05시 night로 구분하고 장소와 시간대가 함께 맞는 이미지만 재사용한다. createdAt은 실제 파일 생성 시각이며 이야기 시간대 판정에 사용하지 않는다. 원래 장소 이름은 유지한다. AI 이미지의 기존 카탈로그에는 이야기 시각이 없으므로 시간 지정 조회에서 재사용하지 않는다. 기존 원본 파일은 삭제하거나 수정하지 않는다. 시간 미지정 직접 첨부 이미지는 공통 배경으로 재사용 가능하다. 시간 지정 첨부는 해당 시간대에만 재사용한다.

이전 아침/낮/밤에 따른 CSS 밝기와 색조 및 모델 광원 변경은 제거했다. 모든 장면에 부드럽게 프리셋(밝기120, 따뜻함10, 색감95, 대비88)을 고정 적용하고 조절 UI를 숨긴다. 이전 로컬 저장값은 이 기본값을 덮어쓰지 않는다. 관리자 부재 시간 테스트는 유지한다.

배경 양 끝의 큰 회색/체크무늬 자리표시자 띠를 화면에서 제외하고 실제 그림 영역을 비율 유지하여 화면에 채운다. 양 끝이 모두 중립색이고 충분히 큰 경우에만 적용하며 한쪽 하늘이나 벽은 유지한다. 원경도 같은 배경 기준 영역과 크기를 적용한다. 극단적으로 잘못 생성된 배경에는 휴리스틱 판정의 한계가 있으므로 신규 생성에는 전체 캔버스 채움 지침도 추가했다. 장소별 시간대 이미지가 처음 필요한 경우 각각 신규 생성 비용이 들고 이후 재사용에는 생성 비용이 없다.

관련 백엔드15개, 프론트35개, 프로덕션 빌드를 확인했다. 실제 저장된 집 PNG로 정지/이동 시 여백 제거와 레이어 정렬을 브라우저에서 확인했다. 새 아침/낮/밤 AI 이미지 품질은 실제 생성 후 별도 확인한다.

식사 활동은 요약에 메뉴를 짧게 넣고, 캐릭터별 말풍선에는 음식과 가까운 이모지 하나만 표시한다. 대응하는 음식 이모지가 없으면 🍽️를 사용한다. 프론트 검사 36개와 빌드를 확인했다.

발화 선은 모델의 현재 좌우 회전을 따라 머리 바깥 3px에 배치하며 나팔 모양도 좌우 반전한다. 정면에서는 모델 로드 시 선택한 임의 방향을 유지한다. 실제 두 VRM과 마르바스 왼쪽 발화 표시를 브라우저에서 확인했고 프론트 검사37개가 통과했다.

## 추가 인형극 동작

RUN/DRINK 활동과 LIGHT/ARMS_CROSSED 자세를 추가했다. 먹기·마시기는 팔을 입 쪽으로 들어 올리고 소품을 함께 표시하며 달리기는 다리 동작과 빠른 가로 스크롤을 사용한다. 기존 모델·데이터에는 새 필드가 없어도 기본 자세로 읽힌다.

활동의 선택된 두 참가자를 interactionActorIds로 지정하고 interaction은 CLOSENESS/AFFECTION/INTIMACY/NONE이다. CLOSENESS는 두 사람이 머뭇거리며 각5px씩, 총10px 가까워진다. AFFECTION은 두 사람 사이에 픽셀 하트가 떠오른다. INTIMACY는 19세 이상과 상호 의사가 기존 설정에서 확인된 장면만 생성하도록 지침을 제한하고 노골적인 묘사는 생성하지 않는다. 표시 자체는 침대와 두 베개 위에서 지속적으로 떠오르는 픽셀 하트뿐이다. 관계 연출을 만들기 위해 사건을 새로 강제하지 않는다.

수면·침대 연출은1.2초간 누운 뒤 모델을 숨기고 다음 활동에서 복원한다. 수면에는 베개에서 Zzz가 올라온다. 동작 줄이기는 정적인 효과를 사용한다. 모델마다 선택적 뼈가 없으면 해당 관절 동작을 건너뛴다. 기존 시간·기억·감정 반영 경로는 유지하며 신규 연출 메타데이터 저장/시간 보정과 잘못된 참가자 차단을 회귀 검사했다. 관련 백엔드51개와 프론트41개가 통과했고 실제 VRM으로 팔짱·수면 숨김·베개 하트·식사·달리기 전환을 확인했다.

## 모델 등록과 시간 체크

기존 resolvePocketSceneModels 조건을 시간 체크에도 연결했다. 선택된 플레이어와 포켓 등록 캐릭터 전체(현재 화면 밖 캐릭터 포함)의 모델 URL과 유효한 양수 키가 필요하다. 활성 캐릭터의 표시 모델도 프론트에서 검사한다. 일반 시간 체크를 켜는 버튼과 치트는 미등록 시 비활성화하고 등록 안내를 표시한다. 이미 ON일 때 OFF로 끄는 동작은 허용한다. 모델 미등록 상태에서는 부재 활동 화면을 열거나 유료 배경 생성을 요청하지 않는다.

서버도 configure/resume/simulate 및 생성 결과 적용 전에 최신 모델 등록 상태를 검사한다. 생성 중 모델이 제거되면 결과 적용을 롤백하고 시간·활동 기록을 변경하지 않는다. 등록 정보 확인이며 외부 모델 파일 다운로드 성공 여부는 기존 모델 로더가 확인한다. 부재 회귀39개·프론트42개·빌드를 통과했고 브라우저에서 ON 차단/등록 후 활성화/모델 제거 후 OFF 전환을 확인했다.
