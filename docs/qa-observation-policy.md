# 연속성 검사는 대화 차단이 아닌 참고 의견

일반 Pocket과 QA 모두 생성된 원문을 저장하고 정상적인 상태·장기기억 처리를 이어간다. 검사기의 approved=false, conflicts, JSON/필드 오류는 대화 취소 사유가 아니다. 검사기 수정본을 본문으로 교체하거나 VERIFY·재생성을 추가 호출하지 않는다.

## 사실과 기억

검사 승인과 사실 변경의 유효성을 분리한다. approved=false라도 원문 근거·이전 값 등 로컬 검증을 통과한 변경은 반영한다. 각 변경을 개별 검증해 한 항목의 잘못된 인용 때문에 다른 유효한 항목까지 폐기하지 않는다. 잘못된 인용/형식의 항목은 검토 기록에 남긴다. 기존 사실과 사용자 입력·저장된 원문은 보존하며 일반 장기기억 추출은 기존 경로로 실행한다. 형식 오류로 사실 추출이 없더라도 원문 저장과 장기기억 처리를 취소하지 않는다.

검사 프롬프트는 최신 사용자 행동을 우선하고 기존 플레이어 상태를 근거로 인정한다. 공동 이동의 자연스러운 생략을 미탑승으로 단정하지 않는다. 기록하지 않은 동작과 명시적 모순을 구분한다. 플레이어 상태만 근거인 내용을 사실 원장에 복제하기 위해 존재하지 않는 인용을 만들지 않는다.

## 기록

일반 스트리밍은 started → delta* → preview → review_warning* → complete 순서다. 경고는 완료를 실패로 바꾸지 않는다. 검토 기록에는 실제 충돌 내용과 후보 본문을 저장하며 phase=ADVISORY로 과거 실패 기록과 구분한다. 기존 소유권 확인·no-store 조회·파일 길이 제한을 유지한다. 경고 파일 저장 실패도 본문 저장을 취소하지 않는다. 스트리밍 외 continue/reroll 경로도 같은 정책으로 처리하고 로컬 기록을 남긴다.

QA는 기존 continuityQa/영수증/보고서 기록을 유지한다. 한 턴에 거절과 잘못된 사실 인용이 함께 있으면 각각의 검토 항목이 생길 수 있다. 100턴 완료가 서사 품질 합격을 의미하지 않는다.

예산·과금 미확인·공급자/통신 오류와 DB 저장 실패는 기존 오류 정책을 유지한다. 무조건 예외를 삼키거나 자동 유료 재시도하지 않는다. 모델 선택은 변경하지 않는다.

## 무료 검증

검사 거절 후 실제 대화·상태 저장, 승인과 무관한 사용자 사실 반영, 일부 잘못된 사실과 정상 사실의 분리 반영, 수정본 미적용·단일 검사 호출, 형식 오류 시 원문 유지, 경고 파일 실패 후 완료 이벤트를 검증한다. H2 모의 QA 100턴은 80개 턴에 검사 문제를 주입하며 원문·사실·기억·영수증 복구를 확인한다. 실제 모델의 의미 정확도는 로컬 테스트로 보증하지 않는다.

이번 변경의 검증 결과: 관련 백엔드 65개와 화면 수신/타이핑 로직 14개, Vite 빌드 통과. QA 모의 100턴에서는 80개 문제 턴의 120개 검토 항목을 기록하며 100턴을 완료한다. 유료 API는 호출하지 않았다.
