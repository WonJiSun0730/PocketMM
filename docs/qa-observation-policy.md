# QA의 연속성 검사: 오류를 기록하고 계속 관찰

100턴 QA는 검사기의 규약 오류나 서사 모순을 찾는 실행이다. 실서비스의 저장 차단 정책과 분리한다. QA 실행 완료는 서사·기억 품질 합격을 뜻하지 않는다.

| 상황 | QA 처리 | 실서비스 처리 |
|---|---|---|
| 검사 승인, 원문 변경 없음, 근거 검증 통과 | 원문 저장, 검증된 사실 변경 적용 | 기존 승인 경로 |
| 검사 미승인 또는 미해결 모순 | 원문 저장, 오류 기록, 사실 변경 폐기 후 다음 턴 | 저장 차단 |
| 검사 JSON/필드 형식 오류 또는 빈 반환 | 원문 저장, 형식 오류 기록, 다음 턴 | 저장 차단 |
| 사실 근거 인용·이전 값 등 로컬 검증 실패 | 원문 저장, 변경 전체 폐기, 다음 턴 | 저장 차단 |
| 검사기가 수정본 제안 | 원문 저장, 제안과 사실 변경을 관찰 기록으로만 보존 | 기존 수정 후 VERIFY 경로 |
| 레거시 사실 초기화 검사 오류 | 해당 이력 묶음 오류 기록, 기존 검증 사실 보존 후 계속 | 기존 저장 차단 |
| 예산·과금 미확인·네트워크/공급자 오류 | 기존 실행기와 지출 보호에 따라 중단, 자동 재시도 없음 | 기존 오류 처리 |

검사 거절을 승인으로 바꾸지 않는다. 검사기의 수정본으로 대상 모델을 대체하거나 자동 추가 호출하지 않는다. QA는 대상 원문을 평가하므로 검사 수정본에 VERIFY를 추가 호출하지 않는다. 일반 소설 생성/상태 적용 자체의 구조 오류나 DB 오류까지 무조건 무시하는 정책은 아니다.

## 적용 범위

SceneContinuityObservation은 명시적으로 연 QA 실행 범위에서만 활성화된다. QaPipeline이 실제 대화 트랜잭션을 이 범위 안에서 실행하며 finally에서 해제한다. 일반 컨트롤러와 실서비스 요청에는 범위가 없고 기존 승인 게이트가 유지된다. 대상 모델은 Luna/Terra/Sol 선택값, 테스트 상대와 내부 판단은 기존처럼 Luna다.

QA DB는 원본 Pocket과 격리된 H2다. 원본 대화와 일반 상태 메타데이터는 기존 경로로 저장한다. 검사기가 제안한 수정 본문/상태와 검증에 실패한 사실은 적용하지 않으며, 사실 변경 묶음은 전부 통과할 때만 적용한다. 이전에 검증한 사실은 그대로 남긴다.

일반 장기기억 추출은 대상 원문을 사용하는 기존 경로로 계속 실행한다. 검사기의 수정본·위조된 사실 변경이 기억 입력에 섞이지 않는다. 대상 원문 자체의 모순/환각은 QA가 관찰할 문제이며 자동으로 정답으로 판정하지 않는다. 모의 테스트 통과를 실제 Luna 의미 품질 합격으로 해석하지 않는다.

## 기록과 복구

모든 관찰은 턴별 Outcome.diagnosticsJson.continuityQa에 정책 OBSERVE_ONLY와 findings로 기록한다. REJECTED, INVALID_JSON, INVALID_FACTS, REPAIR_PROPOSED를 구분하고 검사 결과와 충돌을 보존한다. 실제 API의 응답 원문은 기존 review-responses 기록으로 확인한다.

이 기록은 대화 저장과 같은 트랜잭션 안에서 QA 전용 qa_turn_receipts.continuity_json에 보존된다. 파일 작성 전에 중단됐더라도 커밋 영수증 복구 시 같은 관찰을 되살리며 생성/검사를 다시 호출하지 않는다. JSON/Markdown과 체험 QA 분석의 CONTINUITY_* 항목에서 오류를 확인할 수 있다. UI에 오류 건수와 턴이 표시된다.

예산 정책 메타데이터에 continuityPolicy=OBSERVE_ONLY를 기록하고 구현 해시에도 관찰 정책을 포함한다. 기존 실행의 설정/기록은 덮어쓰지 않는다. 변경된 코드에서는 새 실행을 만들어야 하며 이전 REVIEW_REQUIRED 실행을 자동 재개하지 않는다.

## 무료 검증

실제 서비스 저장·사실 스냅샷·기억 경로를 사용하는 100턴 H2 통합 테스트에서 검사 거절/형식 오류/가짜 근거/수정 제안 80건을 섞어도 완료 100턴, 생성 100회, 검사 100회임을 검증한다. 원문 보존, 검증된 기존 사실 보존, 검사기 오염 사실의 미저장, JSON/Markdown 오류 표시, 같은 요청 ID 재조회와 파일 작성 전 중단 후 복구도 검증한다. 별도 테스트로 실서비스 차단 유지, BOOTSTRAP 오류 관찰, 네트워크·예산 예외 전파와 실행 범위 해제를 확인한다. 유료 API 재실행은 하지 않는다.

최종 결과: 백엔드 관련 테스트 48개 통과(실패/오류/건너뜀 0), 프론트엔드 요청·모델·예산 테스트 3개 통과, 수정 화면 lint와 diff 공백 검사 통과. 유료 호출 및 배포 없음.
