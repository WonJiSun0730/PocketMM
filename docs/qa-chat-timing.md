# 자동 QA 단계별 도착 대기 계측

## 적용

실제 비용·체감 자동 QA도 본문 조기 준비 시간을 기록한다. 치트의 QA 실행 분석 및 각 턴에서 확인한다.

- 본문 준비: QA 대상 요청의 트랜잭션 시작 전부터 생성 본문의 로컬 구조 검증 직후까지. 실제 사용자 스트림에서 preview를 내보내는 시점과 같다.
- 연속성 검사 완료: 같은 시작점부터 연속성 검토·사실 근거 검증 종료까지. QA의 관찰 오류도 검사를 마친 것으로 측정하며 품질 합격을 뜻하지 않는다.
- 저장·기억 포함 처리 완료: 같은 시작점부터 커밋 및 AFTER_COMMIT 기억 처리 반환까지. 이후 테스트 보고서용 진단 수집 시간은 포함하지 않는다.

세 항목은 누적 시간이다. 마지막 항목에서 첫 항목을 빼면 본문 준비 후 후속 처리 대기를 비교할 수 있다. 플레이어 AI의 입력 생성 시간과 브라우저 네트워크·화면 표시 지연은 제외한다. 따라서 **서버 본문 준비 시간**이며 실제 브라우저 도착 실측이라고 표시하지 않는다. 직접 채팅의 브라우저 계측은 기존 별도 치트에서 유지한다.

## 저장과 복구

QA에만 활성화한 ThreadLocal 계측을 사용하고 finally에서 해제한다. 모델 선택·승인 정책·호출 수를 변경하지 않는다. System.nanoTime의 차이를 사용한다.

대화 커밋과 같은 qa_turn_receipts에 본문·검사 시점의 timing_json을 저장한다. 커밋·기억 처리가 반환되면 완료 시점을 갱신한다. Outcome.diagnosticsJson.chatTiming에 포함해 원본 JSON과 각 턴 기록에 보존한다. 보고서 저장 전 장애로 복구해도 기존 영수증의 측정값을 복원하며 재생성하지 않는다. 완료 시점 저장 전 장애는 완료 시간이 null로 남는다.

실패 요청도 관측된 단계까지만 failedOutcome에 보존하고 완료 턴 통계에서 제외한다. 각 단계가 없는 과거 기록은 null/빈 CSV/미측정으로 유지한다. 0ms와 미측정은 구분한다.

## 표시 및 내보내기

- QA 치트: 구간별 최소·최대·평균·표본 수, 턴별 누적 시간, 중단 요청의 부분 측정.
- 전체 JSON: diagnosticsJson.chatTiming 및 currentAnalysis의 chatTiming 요약/턴별 필드.
- 분량·시간 CSV: qa_body_ready_ms, qa_review_complete_ms, qa_processing_complete_ms 열 추가.
- Markdown: 서버 기준 단계별 통계와 분석 원본.

진행 중인 기존 워커에는 소급 적용하지 않는다. 테스트가 끝난 뒤 pull하고 백엔드를 재시작·화면 새로고침한 다음 새로 시작하는 QA부터 기록된다. 서버/워커 코드 해시에도 계측 클래스를 포함하므로 버전 불일치를 확인 없이 진행하지 않는다. 기존 실행을 자동 재개하지 않는다.

## 무료 검증

모의 100턴 실제 H2 경로에서 80건의 검사 관찰 오류에도 100턴 전체에 본문·검사·기억 완료 시점이 존재하고 순서가 맞는지 확인한다. 영수증 복구가 측정값을 보존하고 누락된 완료 시점을 만들어내지 않으며 추가 생성을 하지 않는지 확인한다. 단위 테스트에서는 단조 시계, 실패 후 범위 해제, 과거/실패 기록의 평균 제외, CSV 신규 열과 미측정 공란, JSON 내보내기를 검증한다. 유료 API를 실행하지 않는다.
