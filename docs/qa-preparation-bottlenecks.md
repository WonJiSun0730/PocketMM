# 생성 전 병목 계측

## 범위

기존 QA의 본문 준비 약 20초를 준비 작업과 생성 경로로 분해한다. 실행 순서, 프롬프트, 모델, 유료 호출 수, 사실 승인·기억 정책은 변경하지 않는다. 계측은 기존 DialogueTiming QA 범위가 있을 때만 활성화한다.

## 누적 시점

- preGenerationMs: QA 대상 요청 시작부터 연속성 사실 준비를 끝내고 생성 게이트웨이에 진입하기 직전까지.
- targetDispatchMs: 같은 시작부터 실제 대상 HTTP 실행 직전까지. QA의 토큰 계수·예산 예약 및 요청 기록을 포함한다. 사전 차단되면 null이다.
- 기존 bodyReadyMs/reviewCompleteMs/processingCompleteMs는 유지한다.

preGenerationMs에는 트랜잭션 진입 등 개별 구간 밖의 소요도 포함한다. targetDispatchMs − preGenerationMs에는 프롬프트/요청 구성·QA 사전 계수·예약 및 디스크 기록 등이 포함한다. 이를 순수 모델 추론 시간이라고 부르지 않는다. 모의 게이트웨이가 실제 HTTP 경로를 지나지 않으면 dispatch와 토큰 계수는 미측정이다.

## 작업별 소요

| 키 | 측정 대상 |
| --- | --- |
| SESSION_LOCK | 대화 세션 잠금·입장 상태 확인 |
| INITIAL_SCENE_SETUP | 필요한 초기 장면 준비. 초기화가 불필요한 턴에는 빠른 확인만 포함 |
| USER_MESSAGE_SAVE | 사용자 원문 저장 |
| PLAYER_STATE_SNAPSHOT | 변경 전 플레이어 상태 조회·직렬화 |
| SCENE_INSTRUCTION | OOC 등 장면 변경 지시 처리. 지시가 없으면 빠른 확인만 포함 |
| TIME_INTERPRETATION | 사용자 입력의 명시적 시간 변경 판단·적용 |
| CONTEXT_BUILD | 설정·등장인물·상태·최근 대화·기억을 포함한 주 문맥 구성 |
| CONTEXT_MEMORY_RECALL | 활성 인물들의 기억 조회. 초기 설정·장면 지시 안에서 호출된 조회도 포함 |
| STATE_SNAPSHOT | 등장인물·시스템의 변경 전 상태 조회. 두 작업의 소요·횟수를 같은 키에 누적 |
| SCENE_FACTS_PREPARE | 이전 연속성 사실 및 필요한 과거 대화 보강 준비 |
| TARGET_GENERATION | 생성 게이트웨이 전체. 프롬프트·예산 사전검증·HTTP 응답·파싱 포함 |
| TARGET_TOKEN_COUNT | 대상 생성 요청의 QA 토큰 계수만 측정. 다른 보조 호출의 계수는 섞지 않음 |

각 작업의 durationMs/count/failedCount를 보존한다. 반복 호출은 턴 내에서 합산하고, 평균은 작업별 턴 합계 기준으로 계산한다. 실행 횟수는 별도로 표시한다. 실패한 작업도 finally에서 시간을 남기고 예외는 그대로 전파한다.

구간은 포함 관계가 있으므로 전체를 더하면 안 된다. 기억 조회는 문맥/초기 설정/장면 지시 등에 포함되고, 대상 토큰 계수는 생성 경로 전체에 포함된다. 최초 측정 영수증은 변경 불가능한 복사본으로 보존해 이후 반복 작업이 과거 스냅샷을 바꾸지 않는다.

## 표시·내보내기

QA 치트의 **생성 전 병목 상세**에서 평균 소요 시간순으로 최소·최대·평균·측정 턴 수·실행 횟수를 확인한다. 각 턴에서도 작업별 시간을 펼쳐볼 수 있다. 기존 기록에 없는 작업은 평균에 0으로 넣지 않는다. 0ms는 실제로 1ms 미만이거나 작업이 바로 반환된 측정이다.

Outcome의 chatTiming.stages, 분석의 chatTiming.stages 및 turns[].preparationStages에 저장한다. CSV에는 qa_pre_generation_ms, qa_target_dispatch_ms와 qa_stage_*_ms 열을 추가하고 Markdown에도 구간 통계를 포함한다. 실패 요청의 부분 계측은 기존 failedAttemptTiming에 남고 완료 턴 평균에는 포함하지 않는다.

유료 API나 사용자 실행의 재시작·자동 재개는 하지 않는다. 현재 진행 중인 QA에는 소급 적용되지 않는다. 종료 후 pull·백엔드 재시작·새 QA부터 적용한다. 이번 변경은 측정이며 시간 절감 효과를 주장하지 않는다.

## 무료 검증

- 단조 시계로 중첩·반복·실패 구간의 소요/횟수, 반환값 유지, 범위 해제, 스냅샷 불변성을 검증한다.
- 실제 H2 모의 100턴에서 각 준비 구간과 순서를 확인한다. HTTP를 거치지 않은 모의 응답에 토큰 계수·전송 시간을 만들어내지 않는다.
- 예산 사전 계수 실패 시 시간과 실패 횟수는 기록하되 대상 HTTP 미전송과 비용 차단 보호가 유지됨을 검증한다.
- 분석에서 작업 실행 횟수와 측정 턴 수를 구분하고, 미측정·0ms를 구분한다. CSV 기존 단계 열도 유지한다.
- 프론트의 평균 내림차순 정렬과 미측정 제외를 검증한다. 프로덕션 빌드와 lint로 화면 연결을 확인한다.

최종 관련 백엔드 테스트 52개(100턴 통합 포함), 프론트 테스트 17개 및 Vite 프로덕션 빌드가 통과했다. HTTP 전송 모의 테스트에서 토큰 계수/전송 시점을 기록하면서도 대상 HTTP 실행이 한 번뿐임을 확인했다. 모델·프롬프트·예산 안전 정책의 변경 및 유료 실행은 없다.
