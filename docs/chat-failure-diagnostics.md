> 검토 기록 표시/권한 변경: ADMIN·DEVELOPER 관리자만 기존 방 소유권 검사에 더해 조회할 수 있습니다. 일반 사용자는 조회 API에서 403을 받고 채팅 스트림에도 상세 검토 기록이 포함되지 않습니다. 채팅 상단 표시는 제거했으며 왼쪽 개발자 도구(모바일은 메뉴의 개발자 도구) 안에서 기본 접힘·최근 10건·최대 높이 320px 내부 스크롤로 표시합니다. 기존 개발자 전용 QA/치트 권한은 확장하지 않습니다. 기록 저장과 대화 진행 정책은 유지합니다.

> 정책 변경: 연속성 거절/형식 오류는 이제 ADVISORY 검토 기록이며 일반 대화도 원문 저장·기억 처리를 계속합니다. 아래 과거 승인 차단 설명보다 [현재 정책](qa-observation-policy.md)이 우선합니다. 과거 실패 파일은 보존합니다.

# 일반 채팅 중단 진단

## 확인한 사실

사용자 화면의 기존 빨간 문구는 PocketChatStreamController가 RuntimeException을 잡아 보내는 공통 failed 이벤트다. 생성, 연속성 검사, 저장, AFTER_COMMIT 기억 처리 중 어느 예외인지 구분하지 않았고, 예외 메타데이터를 서버에 남기지도 않았다. 이번에 이미 발생한 예외의 원인은 제공된 화면과 React 콘솔 경고만으로 확정할 수 없다. 새 방이 아니라서 실패했다고 판단할 근거도 없다.

브라우저의 React key 경고는 별도 문제다. PocketPage의 데스크톱/모바일 장면 시스템 목록이 실제 응답의 systemId 대신 없는 id를 key로 사용했다. 두 위치를 systemId로 맞췄다. 이 렌더 경고를 서버 예외의 원인으로 취급하지 않는다.

## 변경

일반 스트리밍 채팅에서도 서버 단계 측정을 열어, 실패하면 다음을 응답에 추가한다.

| code/phase | 의미 |
| --- | --- |
| CONTINUITY_REJECTED | 연속성 검사에서 승인되지 않음. BOOTSTRAP이면 phase는 PREPARATION일 수 있다 |
| CHAT_PREPARATION | 본문 생성 전 준비에서 실패 |
| CHAT_GENERATION | 생성 경로 진입 후 전체 후보 본문 확정 전 실패 |
| CHAT_CONTINUITY | 전체 후보 본문 준비 후 검사 완료 전 실패 |
| CHAT_PERSISTENCE_OR_MEMORY | 검사 완료 후 상태 반영/저장/기억 처리에서 실패 |

이 구분은 관찰한 마지막 단계에 따른 범주이며 개별 실패 원인을 단정하지 않는다. 예를 들어 PERSISTENCE_OR_MEMORY로 DB rollback을 단정하면 안 된다. AFTER_COMMIT 실패일 수 있기 때문이다. CONTINUITY_REJECTED는 예외 cause chain의 승인 거절 타입을 확인한다.

failed 이벤트에는 code, phase, UUID requestId와 한국어 메시지를 넣는다. 기존 브라우저 오류 표시에서 메시지와 번호를 볼 수 있다. 서버에는 같은 번호·세션 ID·예외 클래스·애플리케이션 스택 위치·단계 시간만 남긴다. 예외 message, 원본 provider body, 프롬프트, 사용자 입력과 인증 정보는 기록하지 않는다. cause chain은 순환과 과도한 길이를 제한한다.

일반 채팅 서버 시간의 source는 POCKET_SERVER, 기존 QA 기본 source는 QA_SERVER로 유지한다. 이 변경은 실제 브라우저 수신 시간이나 QA 영수증을 섞지 않는다. 승인 정책을 완화하거나 미검증 본문을 저장하지 않는다. 자동 재시도·새 유료 호출·새 방 생성·기존 데이터 수정은 하지 않는다.

## 기존 방과 적용

기존 방도 계속 사용하도록 설계돼 있으며, 과거 기록 보강이 필요한 경우 BOOTSTRAP을 수행한다. 본문 이후 거절이라도 검사 결과, 형식 오류, 상태/기억 영속화 중단 등 가능성이 여럿이므로 방을 지우거나 새로 만들어 원인을 우회하지 않는다.

현재 실패 건에는 새 오류 번호를 소급 생성할 수 없다. pull 후 진행 중 QA 종료 시 백엔드를 재시작하고 화면을 새로고침하면 이후 실패부터 번호가 남는다. 원인 수집만을 위해 유료 메시지를 재전송하지 않는다. 정상 사용 중 다시 오류가 나면 화면의 code/requestId와 백엔드의 같은 번호 행으로 조사한다.

무료 검증은 실패 단계 분류, 원문 비노출, cause 순환 제한, 기존 방의 검사 거절 1회 호출/추가 생성 없음, 기존 월드라인과 100턴 모의 QA 보존을 포함한다. 이 검증으로 사용자가 겪은 특정 실패의 원인을 재현했다고 주장하지 않는다.

최종 관련 무료 백엔드 49개·화면 로직 10개와 Vite 프로덕션 빌드 통과. 유료 API와 사용자의 실패 요청 재실행은 없었다.

## 거절 사유와 검사 대상 보존

CONTINUITY_REJECTED 예외가 담은 approved/conflicts/필수 항목 누락을 실패 응답의 reviewFailure에 전달한다. 검사기 판단과 실제 서사 오류를 구분해 화면에 표시한다. 단순 거절 코드만으로 오탐이나 실제 충돌을 확정하지 않는다. 검사 단계는 답변 검사/수정본 재검사/이전 대화 보강 검사로 표시한다. VERIFY 실패에는 최초 preview 대신 실제로 재검사한 수정본을 보존한다. API 예외 메시지와 provider 응답 전체는 이 기록에 넣지 않는다.

전용 로컬 저장소 `data/pocket-chat-failures/{sessionId}`에 UUID별 JSON을 임시 파일→원자적 이동으로 보존한다. 대화 DB 트랜잭션 취소와 별도이며, 재시작 후에도 읽을 수 있다. 폴더는 Git에서 제외한다. 환경 설정 `pocket.chat-failure-directory`로 위치를 바꿀 수 있다. 기록에는 번호·포켓 ID·시각·검사 단계·승인 상태·거절 조건·충돌 설명·검사 대상 본문만 들어간다. 사용자 입력/전체 프롬프트/공급자 envelope/인증 헤더는 저장하지 않는다. 충돌 20개(각 2,000자), 본문 32,000자로 제한하고 잘림 여부를 표시한다. 원본 대화와 별도인 진단 자료이며 대화 기록으로 재주입하지 않는다. 오래된 파일은 자동 삭제하지 않으며 UI에서는 최근 10건을 읽는다.

조회는 기존 방 소유권과 world/room/session 범위를 확인한 GET `/api/worlds/{worldId}/rooms/{roomId}/sessions/{sessionId}/chat/failures`만 제공한다. HTTP 캐시는 no-store다. 화면은 처음 열 때 기록을 읽고, 새 실패 응답은 즉시 병합해 오류 번호의 상세를 펼친다. 다른 포켓의 기록은 합치지 않는다. 별도 파일 저장이 실패해도 원래 거절 원인과 현재 화면의 설명을 유지하며, 영구 저장 실패 안내를 표시한다. 자동 재생성/새 유료 호출/거절 무시/검사 기준 변경은 없다. 일반 메시지 스트리밍 경로에 적용하며 리롤·계속하기의 기존 오류 경로는 이번 범위 밖이다.

기존 번호 `26b101ba-8344-4727-89ec-c39cb81a5db2`의 사유는 당시 저장되지 않아 소급 복구하지 못한다. 새 코드는 이후 발생 건부터 보존한다. 이를 특정 오탐의 원인 해결이라고 주장하지 않는다.

보완 후 무료 백엔드 55개, 화면 로직 13개와 프로덕션 빌드 통과. 디스크 재조회·포켓 격리·길이 제한·빈 충돌/누락·VERIFY 본문 선택·소유권/다른 world 차단·디스크 실패 시 응답 유지와 단일 생성 호출을 검증했다. 모의 실제 서비스 100턴/검사 오류 80건도 보존했다. Vite `/test-fixtures/rejection-evidence.html`에서 실제 표시 컴포넌트와 수신기로 구체적 사유 및 본문 펼치기를 무료 검증했다. 스크린샷은 별도 결과물에 보존했다. 유료 실행은 없었다.
