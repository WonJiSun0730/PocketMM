# 채팅 오류 사례 수집

## 플레이어 서술 범위 회귀 사례 (2026-10-12)

일반 사용자 입력과 자동 진행 1~2회에서는 새로운 의도·평가·지식·감정·대사·동의를 대신 만들지 않는다. 사용자가 정한 행동의 구체적인 실행 과정은 확장할 수 있다. 연속 자동 진행 3~5회는 현재 작업 안의 짧은 대사나 작은 반응을 허용하고, 6회부터는 기존 상황과 성격에 맞는 일상 대사·되돌릴 수 있는 행동을 대리 서술할 수 있다. 모든 단계에서 다음 행동·답변의 여지를 남긴다. 조종 금지가 켜져 있으면 횟수와 관계없이 새 동작도 추가하지 않고 사용자가 작성한 행동과 외부 결과만 묘사한다.

| 입력/상황 | 허용되는 전개 | 실패 판정 |
| --- | --- | --- |
| 밀리가 쿠키 틀을 준비하고 구울 준비를 했다 | 틀 모양, 재료 배치, 버터와 설탕을 섞는 등 준비 절차를 풍부하게 묘사 | 다른 사람에게 잔소리, 선물 대상 선택, 준비 지시를 굽기·배달 완료까지 확대 |
| 문을 두드렸다 | 노크 소리, 내부 풍경, NPC의 반응 | 입실·서류 제출·브리핑 답변·견학 동의를 플레이어 대신 연달아 진행 |
| NPC가 제안하거나 질문했다 | NPC의 말과 태도, 주변 반응, 사용자가 답할 여지 | 짧은 끄덕임으로 동의를 확정하거나 한두 마디라도 플레이어 답을 창작 |
| 조종 금지 꺼짐 상태, 연속 자동 진행 1~2회 | 이미 시작한 행동의 과정과 NPC·환경을 전개 | 횟수와 무관하게 처음부터 대리 대화, 과거 AI가 만든 대사를 근거로 적극성 확대 |
| 연속 자동 진행 3~5회 | 현재 작업 안에서 짧은 대사·작은 반응, 필수는 아님 | 새로운 목적·지식을 만들거나 NPC 질문에 대한 플레이어 답을 연달아 생성 |
| 연속 자동 진행 6회 이상 | 상황과 성격에 맞는 일상 대사·행동, 한 장면 단위 | 중대한 관계·위험·비가역적 선택을 확정하거나 다음 선택의 여지까지 소진 |
| 행동의 재료·절차를 짧게 작성 | 맥락에 맞는 평범한 절차를 채워 서술 | 문장을 그대로 반복하거나 모든 세부 동작을 사용자에게 다시 요구 |

플레이어 프로필만으로 선택을 대신 수행할 수는 없다. 허용 범위는 현재 서버가 전달한 자동 진행 단계나 명시적인 사용자 위임을 따른다. 세계관 사실과 플레이어가 아는 사실도 구분한다. 문장 수보다 의미상 결정권을 검사한다. 높은 단계에서도 한 번에 질문·답변·완결을 거듭해서 사용자의 다음 선택을 소진하면 실패다.

횟수는 성공한 자동 진행 메시지에 저장한다. 사용자 대사·지문(OOC 포함)을 전송하면 새 답변은 자동 진행 회차가 아니므로 다음 자동 진행은 1회다. 리롤·버전 변경·새로고침은 회차를 늘리지 않는다. 자동 진행을 삭제하면 남은 마지막 메시지의 회차에서 이어간다. 생성 실패도 회차를 늘리지 않는다. 기능 반영 이전 메시지에는 회차가 없으므로 다음 자동 진행부터 1회로 시작한다. 조종 금지가 켜져 있어도 연속 횟수 자체는 저장하지만 플레이어 조종은 허용하지 않는다.

대화 테스트에서는 2→3회, 5→6회 경계, 6회 이후 사용자 입력→다음 자동 진행 1회, 6회 답변 리롤의 회차 유지, 조종 금지 켜짐 상태의 6회 진행을 함께 확인한다. 문제 기록의 생성 입력(modelInput)에도 당시 회차와 단계가 포함된다.

코드 검사는 공통 시스템 프롬프트 및 자동 전개/리롤의 경계를 확인한다. 실제 생성 품질은 별도로 Gemini/OpenAI에서 위 사례와 반례를 실행해 확인한다. 프롬프트 검사가 통과했다고 모델의 모든 출력이 보장되지는 않는다.

AI 답변 아래의 **문제 기록** 버튼으로 사례를 저장할 수 있다. 모든 경우를 미리 찾을 필요는 없다. 실제 실패 한 건과 비슷하지만 정상 처리해야 하는 반례를 함께 모으는 방식으로 늘린다.

## 화면에서 기록하고 전달하기

1. 문제가 나온 답변에서 **문제 기록**을 누른다. 리롤한 답변이면 화면에 선택된 버전이 기록된다.
2. 문제 종류, 실제 문제, 기대했던 결과를 적고 저장한다. 입력·답변 원문, 전후 장면 상태, 생성 당시 모델·설정과 직전 최대 6개 메시지는 함께 저장된다. 추가 AI 호출은 없다.
3. 포켓 상단의 **문제 기록 관리**에서 모든 포켓의 저장 기록을 확인한다.
4. **문서 내려받기 (.md)**를 누른 뒤 내려받은 파일을 이 채팅에 첨부한다. **원본 데이터 (.jsonl)**는 기계적으로 비교하거나 나중에 평가 자료로 사용할 때 함께 전달할 수 있다.
5. 수정 후 재테스트해서 해결을 확인한 기록은 관리 화면의 **삭제**로 직접 지운다. 기록 삭제는 대화 내용을 지우지 않는다.

기록은 서버 DB에 저장되므로 새로고침·재로그인 뒤에도 남는다. 저장한 문제는 리롤·재생성·포켓 삭제로 사라지지 않는다. 문서에는 이미 내려받은 시점의 자료가 남으므로 삭제 후 공유할 문서는 다시 내려받는다. 다른 계정의 기록은 조회하거나 삭제할 수 없다.

기능 반영 전 생성된 답변에는 생성 당시 설정이 없다. 이 경우 입력과 직전 대화는 기록 시점의 참고값으로 표시하고, 알 수 없는 과거 설정을 추정해 채우지 않는다.

화면에서 저장하지 못했거나 별도 상황 설명이 필요할 때는 아래 양식을 사용한다.

## 복사해서 쓰는 양식

```text
사례 이름:
분류: 시간 / 등장인물 / 캐릭터 설정 / 플레이어 조종 / 지문 품질 / OOC / 기타
모델: 포켓 설정에 표시된 제공자와 모델 이름
플레이어 조종 금지: 켜짐 / 꺼짐
관련 설정: 월드·캐릭터·플레이어의 필요한 부분만

입력 직전 현재 장면: 날짜·시각 / 장소 / 소지품 / 상태
직전 대화: 문제 이해에 필요한 앞부분 2~5턴
문제를 만든 사용자 입력: 별표·OOC 표기를 포함한 원문 그대로
AI 답변: 지문과 대사 원문
출력 직후 현재 장면: 날짜·시각 / 장소 / 소지품 / 상태

기대 결과:
실제 문제:
사용한 동작: 일반 전송 / 자동 전개 / 리롤 / 입력 수정 후 재생성
리롤 결과: 미실행 / 정상 / 같은 문제 / 다른 문제
```

로그인 비밀번호, 앱 비밀번호, API 키는 포함하지 않는다. 화면에 표시된 본문과 상태를 함께 남긴다. 수면 문장처럼 별표 하나 차이로 계산 경로가 달라질 수 있어 원문이 중요하다.

## 기대 결과는 무엇을 적나

시간·등장인물·소지품은 명확한 정답을 적는다. 예: 10월 8일 15:30에서 `*3일 후, 오후 3시에 잠들어 6시간 잤다.*` → 10월 11일 21:00. 이어서 `*이후 6시간 더 잤다.*` → 10월 12일 03:00.

소설 품질은 정답 문장 대신 기준을 적는다. 예: 자동 전개이고 조종 금지가 꺼졌으므로 플레이어도 상황에 맞는 대화를 주고받는다. 한 문장으로 입력을 반복하지 않고, 구체적인 행동과 반응이 연결된 장면을 보여준다. 잠든 장면에서는 억지 대사를 요구하지 않는다.

## 이번 수정 확인용 짧은 테스트

1. 조종 금지를 끄고 유미와 함께 편의점에서 먹을 것을 고르는 장면을 만든 뒤 자동 전개를 누른다. 플레이어도 자연스럽게 말하고 일상적인 선택을 하는지 확인한다.
2. 같은 상황에서 조종 금지를 켠 뒤 자동 전개와 리롤을 한다. 새 플레이어 대사·행동·감정을 대신 쓰지 않는지 확인한다.
3. `*5분 기다렸다.*`를 보낸다. 5분을 초침 다섯 칸으로 쓰거나, 시간만 보고하는 단답으로 끝내는지 본다.
4. 위의 별표 포함 복합 수면과 추가 수면을 보낸다. 본문과 현재 장면의 날짜·시각이 모두 맞는지 확인한다.
5. 퇴장한 마르바스가 다시 끼어들지 않는지도 함께 확인한다. 지문을 풍부하게 만든다는 이유로 등장인물을 되돌리면 실패다.

## 모은 사례를 쓰는 순서

- 원본 실패를 재현하고, 문맥 전달·규칙 계산·상태 저장·프롬프트 중 어느 부분의 문제인지 확인한다.
- 실패 사례를 고친 뒤 원본과 반례를 함께 재검증한다. 예: 수면 완료는 시간을 이동하고, `6시간 잘 계획이다`는 수면 완료로 계산하지 않는다.
- 모델 품질은 같은 설정에서 첫 결과와 리롤 몇 개를 따로 보관한다. 좋은 답변만 고르지 않고 실패도 남겨 빈도를 비교한다.
- 같은 원인으로 난 사례는 묶는다. 정확한 상태 정답이 필요한 항목은 자동 테스트로, 소설 품질은 실제 모델 대화 평가로 확인한다.
- 반복되는 실패가 충분히 모이면 사람이 검토한 사례로 학습 데이터와 별도 평가 데이터를 만든다. 처음부터 새 머신러닝 모델을 만드는 것보다 이 평가 자료를 바탕으로 기존 모델의 프롬프트와 문맥을 개선하는 것이 먼저다.

이번 자동 테스트는 입력 해석과 모델에 전달되는 지시를 검증한다. 실제 소설 문장의 개선 여부는 위의 대화 테스트로 확인해야 한다.
