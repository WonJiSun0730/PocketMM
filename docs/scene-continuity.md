# 장면 연속성 보호

2026-10-22 비용 최적화 후의 검사 모델 선택, 캐시 경계 및 변경량 최소화는
[연속성 검사 비용 최적화](continuity-cost-optimization.md)를 참조한다.
아래 '같은 선택 모델' 설명은 기본 동작이며 OpenAI 검사 전용 설정이 있으면 검사에만 적용한다.

## 기존 구조 재사용

Pocket의 WorldRoomDialogueService에서 대화, 자동 전개, reroll, regenerate의 생성 결과를 저장하기 전에 검사한다. 기존 DialogueGateway, 공급자 라우터, AiUsageTracker, 응답 버전별 스냅샷을 재사용한다. 별도 대화 저장소나 AI 클라이언트는 만들지 않는다. 레거시 1:1 ChatService와 부재 활동 생성 자체에는 적용하지 않는다. 부재 활동 뒤 Pocket 응답을 생성할 때에는 해당 활동 기록을 반영한다.

플레이어 위치·상태·소지품, 등장인물 출입, 시스템 수치는 기존 저장 구조가 담당한다. 장면 사실 기록은 개별 인물 식별, 물품 소지자, 문서 번호의 종류, 전달·수신 확인, 열람·완료 상태와 미해결 단서를 보완한다.

## 처리 순서

1. 해당 메시지 이전의 선택된 응답 버전에서 마지막 사실 기록을 읽는다.
2. 기록 이후 확정된 대화가 있으면 메시지 ID 순으로 12개씩 읽어 사실을 보충한다. 최근 6턴 제한으로 과거 사실을 버리지 않는다.
3. 사실 기록을 매 생성의 동적 프롬프트에 넣는다. 장기기억 검색과 독립적이며 정적 캐시 부분을 변경하지 않는다.
4. 기존 경로로 응답을 생성한다.
5. 같은 공급자·선택 모델로 본문과 상태 메타데이터를 검사한다. 변경이 없으면 승인만 반환해 본문 복사 비용을 줄인다.
6. AI 본문을 수정했다면 한 번 더 검사한다. 반복 수정은 하지 않는다.
7. 코드에서 원문 인용, 이전 값, 키 중복, 관찰·주장 구분, 메타데이터 범위를 검증한다.
8. 통과한 응답과 상태만 저장하고 기존 기억 처리로 넘긴다. 실패하면 기존 대화 트랜잭션이 롤백된다.

의미적 모순 판정은 모델에 의존한다. 코드 검증은 근거 없는 변경 형식, 잘못된 출처, 오래된 이전 값, 주장으로 관찰을 덮어쓰는 시도를 막지만 모든 자연어 모순을 증명하지는 않는다.

## 사실과 사용자 의도

SceneFacts는 최대 96개의 짧은 활성 사실을 관리한다. 종류는 PERSON, POSSESSION, IDENTIFIER, DELIVERY, COMPLETION, UNCERTAIN이며 확실성은 OBSERVED, CLAIM, INFERENCE이다. 주장은 별도 키에 보존한다.

각 변경에는 기존 키와 정확한 이전 값, 새 값, 변경 사유, 실제 원문에 포함된 인용이 필요하다. 경찰 사건 번호와 병원 접수 번호, 문서 보관과 열람 완료, 전달과 최종 수신을 구분한다. 완료되어 이후 전개에 무관한 사실만 근거와 함께 정리한다. 한도를 넘으면 무작위로 버리지 않고 저장을 중단한다.

사용자 발언을 교정하거나 거부하지 않는다. 사용자 서술·전개 방향·OOC 설정 변경은 의도적 수정으로 허용한다. 등장인물의 보고·추측은 주장으로 기록한다. OOC 질문이나 문체 요청만으로 장면 전체를 초기화하지 않는다. 이 구분은 문맥을 읽는 검사 모델이 판단한다.

## 버전·편집·삭제

WorldRoomMessageVariant의 beforeSceneFactsJson, afterSceneFactsJson에 기록한다. 선택된 버전을 따라 읽으므로 대안 응답의 사실이 다른 전개에 섞이지 않는다. 재생성과 삭제는 대상 이전 기록을 읽는다.

직접 편집 시 해당 지점 이후 모든 응답 버전의 사실 캐시를 무효화한다. 다음 생성에서 수정된 실제 대화로 재구성한다. 직접 편집한 문장을 자동 수정하지 않는다.

## 비용과 실행 기록

매 응답에 검사 1회, 수정 시 검증 1회가 추가된다. 최초 이력 초기화·수정된 이력 재구성에는 12개 메시지 묶음마다 추가 호출이 생긴다. 동일한 공급자·선택 모델을 쓰며 OpenAI Pocket에서 Gemini로 전환하지 않는다.

SCENE_CONTINUITY 목적의 사용량으로 기록한다. Experience QA는 TARGET과 별도의 AUXILIARY 비용으로 분류하고 출력 상한과 사전 비용 예약을 적용한다. UI 추정에는 검사·수정 검증 비용을 포함하지만 최초 이력 재구성은 대화 길이에 따라 추가된다.

hard-cap-v2-scene-continuity 정책을 사용한다. 이전 QA 기록을 삭제하거나 새 정책으로 몰래 재개하지 않으며 새 실행이 필요하다. 기존 SQL 복제의 SELECT * 경로가 새 열도 보존한다. 평가 컨텍스트에 생성 당시 사실도 기록한다.

## 스키마와 검증

기존 Hibernate ddl-auto=update 설정에서는 nullable LONGTEXT 열 2개가 추가된다. 수동 스키마 관리 환경은 열 유무를 확인한 뒤 다음 변경을 적용한다.

    ALTER TABLE world_room_message_variants
      ADD COLUMN before_scene_facts_json LONGTEXT NULL,
      ADD COLUMN after_scene_facts_json LONGTEXT NULL;

기존 데이터는 삭제하거나 일괄 재작성하지 않는다. 사실 기록이 없는 대화는 다음 Pocket 응답 생성 때 초기화한다.

회귀 테스트는 숫자·순번, 번호 종류, 소지자 근거, 열람 완료, 사용자 설정 변경, 검사 실패 차단, 수정 재검증, 6턴 밖 사실 공급, 이력 페이지 처리, 대안 선택·삭제·편집 후 재구성을 다룬다. 유료 모델의 실제 장기 QA는 별도 검증이다.

## 2026-10-22: 검사 요청과 최근 이력 최적화

- 일반 대화의 사용자 입력+AI 답변을 1턴, 자동 전개의 AI 답변도 각각 1턴으로 센다. 최근 완료 응답 6개와 그에 대응하는 사용자 입력, 현재 미완료 사용자 입력을 유지한다. DB 조회도 7번째 이전 AI 응답을 경계로 제한한다. 자동 전개 30회 뒤에는 최근 6개만 원문으로 제공한다. 원본 대화·UI 페이지·장면 사실·기억은 삭제하지 않는다.
- 두 공급자의 reviewWorldRoomContinuity가 검사 전용 요청을 구성한다. 소설용 NARRATOR·진행 지침·일반 역할극 응답 envelope를 쓰지 않고 approved/turn/changes/conflicts JSON을 직접 받는다.
- SceneContinuityRequest가 설정·프로필·현재 상태·관련 기억·최근 대화를 검사 근거로 제공한다. 캐릭터 프로필이나 월드 지침의 반복은 정리하지 않는다. facts는 기존 검사 자료 한 곳에만 넣고, 현재 사용자 입력은 최근 이력에서 중복하지 않는다. BOOTSTRAP에는 해당 이력 묶음만 제공하며 이후 recentMessages를 섞지 않는다. 역사 속 사용자 입력은 역할이 있는 history에서 읽는다.
- 기존 RestClient, 인증, OpenAI 사용량 파싱·전송 실패 기록, Gemini 재시도·본문 추출·사용량 집계와 공급자 선택을 재사용한다. 승인/수정 재검증, 인용 검증, 버전별 사실 저장과 실패 시 롤백은 유지한다. 검사 모델과 호출 횟수는 줄이지 않는다.
- 동일 지침·합성 자료로 이전 요청 모양과 분리한 요청을 비교한 테스트에서, 직렬화 요청 전체의 o200k_base 추정은 6,801 → 1,954토큰이다(4,847토큰, 약 71.3% 감소). 실제 청구 입력·캐시·응답 비용이나 실사용 세션의 절감률이 아니다. 원시 재현 결과는 SceneContinuityRequestTest 실행 시 target/request-history-optimization.json에 생성한다.
- 유료 모델 호출 없이 실제 공급자 요청을 인터셉터에서 검사하고, 최근 6턴의 일반/자동/혼합/재생성 경계, 전체 원본 이력 보존, 사실·현재 입력 1회 전달, BOOTSTRAP 시점 격리, 공급자 선택·사용량 기록·기존 소설 프롬프트 유지와 합성 토큰 변화를 검증한다.
